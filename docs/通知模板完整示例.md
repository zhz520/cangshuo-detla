# 公众号与业务短信完整模板示例

以下八份示例分别对应客户、打手、管理员、客服的公众号模板组和短信模板组。每份示例都覆盖五类事件：`new_order`、`order_status`、`refund_status`、`complaint_status`、`staff_review`。

示例中的模板 ID、短信模板 Code 和左侧变量名是占位文字。上线前必须替换为微信公众号模板或阿里云已审核模板中的真实值；右侧数据源名称保持不变。

通知配置页的每个模板组字段下方也可直接展开并复制完整示例。

> 示例中的订单号、退款单号、客户“阿岚”、打手“林川”、金额和时间均为虚构数据。上线前，模板 ID、短信模板 Code 和左侧变量名必须替换为当前平台审核通过的真实值，右侧系统数据源保持不变。

## 一、配置前先确认三件事

1. **模板组不决定接收人。** 某个角色填写了模板，不代表该角色一定会收到每个事件。实际发送仍按事件来源、订单参与人、后台权限、客服是否上班、打手是否在线以及公众号绑定状态路由。
2. **五个事件分组建议全部配置。** 未配置当前事件时，系统会尝试旧版通用模板；角色模板和旧版模板都没有有效内容时，本次投递记录为“模板未配置”。如果业务暂时不用某类通知，也应先配置一个审核通过的兜底模板。
3. **公众号和业务短信是两套通道。** 公众号可承载较长的结构化内容；短信必须使用服务商审核通过的签名与模板。两者的 fields 右侧都只能使用本文列出的七个系统数据源。

## 二、五个事件分组怎么用

| 事件键 | 页面名称 | 触发范围 | 建议重点 |
|---|---|---|---|
| <code>new_order</code> | 新订单 | 订单支付成功或新订单进入处理流程 | 订单号、商品、金额、是否已指派、是否有人在线 |
| <code>order_status</code> | 订单状态 | 指派、接单、开始服务、完成、确认等履约变化 | 当前状态、客户、打手、时间 |
| <code>refund_status</code> | 退款与提现 | 退款申请、初审、终审、执行结果，以及提现完成或驳回 | 退款/提现状态、金额、退款单号、处理结果 |
| <code>complaint_status</code> | 投诉处理 | 新投诉、申诉、投诉退款待终审、仲裁完成 | 处理状态、订单、客户、处理结果 |
| <code>staff_review</code> | 人员审核 | 打手入驻、主页素材审核、冻结与解冻 | 审核状态、申请人/打手、审核结果、时间 |

客户角色的 staff_review 示例用于保留统一五分组结构，并提供“账号资料审核”类内容的预演；当前版本实际人员审核事件主要发送给打手、管理员和有相关权限的上班客服。

## 三、字段说明：左侧变量名与右侧数据源

公众号模板组格式：

<pre><code>{
  "order_status": {
    "templateId": "微信后台模板 ID",
    "fields": {
      "thing1": "message",
      "character_string2": "orderNo",
      "phrase3": "status"
    }
  }
}</code></pre>

- templateId：微信公众号“我的模板”详情中的模板 ID。一个事件对应一个模板 ID。
- fields 左侧：公众号模板正文中的占位变量名，不带 {{、.DATA 和 }}。例如正文 {{thing1.DATA}} 对应左侧 thing1。
- fields 右侧：系统数据源名称，只能使用下表七个值。
- fields 的顺序不影响发送；字段名和右侧数据源必须完全匹配。

| 右侧数据源 | 作用 | 示例值 | 注意事项 |
|---|---|---|---|
| <code>message</code> | 系统按角色拼好的完整业务正文 | 订单支付成功，等待打手接单 | 适合正文或备注；公众号字段可能限制长度 |
| <code>status</code> | 系统事件对应的短状态 | 新订单 | 如“退款已初审”“主页素材待审核” |
| <code>time</code> | 通知生成时间 | 2026-11-08 20:30:00 | 短信统一使用 yyyy-MM-dd HH:mm:ss |
| <code>orderNo</code> | 订单号 | DG202611080001 | 非订单审核事件通常为 - |
| <code>amount</code> | 订单金额 | 68.00 | 两位小数；没有关联订单时为 0.00 |
| <code>customerName</code> | 客户昵称 | 阿岚 | 没有客户资料时为 - |
| <code>playerName</code> | 打手昵称 | 林川 | 未指派时显示“未指派” |

当前发送实现会按公众号字段名前缀截断：thing* 最多 20 个字符，phrase* 最多 5 个字符，character_string* 最多 32 个字符，time* 最多 19 个字符，其他字段最多 200 个字符。请复制公众号模板实际字段名；不要在不了解字段类型时把长正文塞进 phrase。

## 四、微信公众号后台怎么找到并填写

1. 登录 mp.weixin.qq.com，选择当前客户正式使用的公众号。模板消息菜单与账号类型、认证状态和平台灰度有关，以后台实际显示为准；没有入口时先在“广告与服务 → 模板消息”申请相关能力。
2. 进入“广告与服务 → 模板消息 → 模板库/我的模板”，选择适合的通知模板并添加到“我的模板”。
3. 打开模板详情，复制 **模板 ID**，填入我们的 templateId。
4. 查看模板正文，例如：

<pre><code>{{thing1.DATA}}
订单号：{{character_string2.DATA}}
状态：{{phrase3.DATA}}
时间：{{time5.DATA}}</code></pre>

其中 thing1、character_string2、phrase3、time5 就是 fields 左侧变量名。
5. 在 fields 右侧填写系统数据源。例如 {"thing1":"message","character_string2":"orderNo","phrase3":"status","time5":"time"}。
6. 保存配置后，让接收人关注该公众号，并在对应客户端“公众号消息通知”入口完成身份绑定。
7. 使用通知记录页观察结果。RECIPIENT_NOT_BOUND 表示未绑定；TEMPLATE_NOT_CONFIGURED 表示模板 ID 或字段为空；WECHAT_40037 类错误通常表示模板 ID 或字段名与公众号后台不一致。

以下正文只用于说明变量如何对应，实际模板标题、字段名和审核结果以微信公众号后台为准。

**新订单**

<pre><code>{{thing1.DATA}}
订单号：{{character_string2.DATA}}

**订单状态、退款与提现、投诉处理**沿用上面的订单字段模板，只替换对应事件的 templateId；如需突出退款单或审核说明，可继续使用 message 正文。

**人员审核**

<pre><code>{{thing1.DATA}}

### 跳转链接怎么处理

微信公众号后台的模板详情里没有“每次发送的点击链接”字段。模板消息的跳转地址是在调用发送接口时通过 url 参数提交，不属于 fields。

当前电竞系统版本只向微信发送 templateId 和 fields，未读取模板 JSON 中的 url。因此：

- 不要把网址填入 fields，否则会被当成未知数据源并保存失败。
- 不要期待在公众号模板里填写链接后自动生效。
- 需要点击模板进入订单页时，应由开发在公众号通知发送接口增加并校验 url，再为不同事件生成客户域名下的可点击地址。
- “公众号通知 → 公众号授权回调页面”只用于身份绑定，不是消息点击跳转地址。

## 五、阿里云短信后台怎么配置

1. 登录阿里云控制台，进入“短信服务 → 国内消息 → 模板管理 → 添加模板”，选择通知类模板。
2. 在模板内容中使用服务商要求的 ${变量名} 格式。例如：

<pre><code>${message}订单号${orderNo}，客户${customer}，打手${player}，状态${status}，金额${amount}元，时间${time}。</code></pre>

3. 提交审核。审核通过后复制模板 Code，通常是 SMS_ 开头的字符串，填入 templateCode。
4. 把正文变量名复制到 fields 左侧并去掉 ${ 和 }。例如正文 ${orderNo} 对应 {"orderNo":"orderNo"}。
5. 在阿里云短信签名管理中申请签名，并将审核通过的签名填写到系统“短信配置 → 阿里云短信签名”。
6. 在“短信配置”中填写 AccessKey ID、AccessKey Secret，并在 RAM 中给该用户最小化的短信发送权限。
7. 短信模板只有审核通过后才能发送。模板变量缺失、手机号为空、签名不一致、变量值与审核模板不匹配都会失败。

短信模板建议只保留与业务真正相关的最少变量。变量越多，审核和计费短信长度越难控制；无法保证审核通过的文案，可先使用服务商已有固定模板。

### 阿里云模板内容示例

**订单类事件（新订单、订单状态、退款与提现、投诉处理）**

<pre><code>${message}订单号${orderNo}，客户${customer}，打手${player}，状态${status}，金额${amount}元，时间${time}。</code></pre>

对应的 fields 示例：

<pre><code>{
  "message": "message",
  "orderNo": "orderNo",
  "status": "status",
  "amount": "amount",
  "customer": "customerName",
  "player": "playerName",
  "time": "time"
}</code></pre>

**人员审核**

<pre><code>${message}审核状态：${status}，时间${time}。</code></pre>

<pre><code>{
  "message": "message",
  "status": "status",
  "time": "time"
}</code></pre>

## 七、常见配置错误

| 现象 | 原因 | 处理 |
|---|---|---|
| 模板未配置 | 当前事件没有有效 templateId/templateCode，旧版通用模板也为空 | 补齐当前角色五类事件，或配置旧版兼容模板 |
| 字段映射无效 | fields 右侧写了网址、手机号、任意中文或未知变量名 | 只能使用七个系统数据源 |
| 公众号模板 ID 无效 | 复制了模板标题、示例 ID，或账号与模板不匹配 | 从“我的模板 → 模板详情”重新复制模板 ID |
| 收件人未绑定 | 用户未关注公众号或没有完成身份绑定 | 在对应客户端重新进入公众号通知入口绑定 |
| 短信手机号缺失 | 客户/打手/员工资料没有手机号 | 补齐手机号后再重试；不要用其他角色手机号代替 |
| 内容被截断 | 公众号字段类型有长度限制 | 使用合适字段；长正文不要映射到 phrase 等短字段 |
| 点击消息不跳转 | 当前版本没有发送公众号 url | 需要开发接入消息跳转 URL，不能把链接写进 fields |
