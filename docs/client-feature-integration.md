# 通用客户端：修复与授权接入

本分支基于 `cangshuo-detla/main`，与独立运营后台 `cangshuo-detla-authorize` 分开维护。没有复制 742 的品牌、Logo、域名、端口、运行数据、支付或短信凭据。

新增功能：图片按原比例完整显示、原图预览与尺寸提示；本地 WebSocket 使用当前站点代理；配置整数校验；新库首次管理员引导；可选付费模块的授权验证、启停及收益对比分析。

## 接入运营中心

1. 从运营中心导出验证公钥，放入客户服务器私有配置目录。不要向客户服务器复制签发私钥。
2. 配置 `PLATFORM_CUSTOMER_ID`（与运营中心客户编号一致）、`PLATFORM_STATE_PATH`（可写且持久保存的实例状态文件）和 `PLATFORM_PUBLIC_KEY_PATH`（公钥文件路径）。未配置客户编号时显示 `unconfigured`，不能导入其他客户的授权。
3. 管理员在「功能与更新 → 功能商城」复制实例 UUID，将客户编号、实例编号、客户端版本和客户使用的域名交给运营人员登记。
4. 授权中心完成在线支付或人工收款后自动签发授权。客户端配置 `PLATFORM_REPORT_URL=https://授权中心域名/api/client/report` 后，会使用签名授权定期自动上报当前版本并同步授权。授权中心只控制授权有效期，客户端管理员自行决定功能是否实际启用。
5. 功能商城的购买和续费由客户端后端请求授权中心创建订单，客户端跳转到授权中心一次性收款页。支付金额由授权中心计算，微信商户密钥和支付回调不会下发到客户端。
6. 更新签发文件包含该实例当前有效模块的完整集合；签发与重复领取均由运营中心保证幂等。旧版单一有效期授权仍可验证。
7. 已由授权中心管理的付费模块，功能商城价格必须使用授权中心同步的 priceCents；授权中心暂未返回价格时显示人工报价，不得回退显示客户端内置历史价格。

此客户端文档对应正式版 `1.5.12`。现有商品、订单、钱包、提现、聊天、打手工作台和收益日报继续使用，基础业务不因更新收费。

## 初次管理员引导

新库可显式设置 `BOOTSTRAP_ADMIN_ENABLED=true`、`BOOTSTRAP_ADMIN_USERNAME`、`BOOTSTRAP_ADMIN_PASSWORD`。仅在管理员表为空时创建账号，已有账号不重置。创建后应关闭引导开关。

## 数据与发布边界

- 保留主库原有迁移脚本和部署资料。不要把仓库内旧种子数据重新导入正在运行的客户数据库。
- 新增 `phone_unique` 的迁移只修复结构；上线前先检查重复手机号并完成备份，不自动清除用户记录。
- 授权状态文件应与客户数据库、配置和上传文件一起纳入备份。删除状态文件会改变实例 UUID，需要重新登记签发。
- 系统更新页从授权运营中心读取正式版目录，按后端、管理后台和 H5 的实际组件版本判断缺口，支持选择非必要更新项及依赖项；服务端计算更新计划、校验正式包，并在执行前备份。
- GitHub 正式版本发布后，由内部维护人员登录客户后台选择更新内容并启动更新；不要要求客户自行点击更新。更新完成后核验组件版本和本地健康检查，失败时使用更新备份回退。授权运营中心不直接登录客户业务后台执行安装。
- 离线授权不能即时撤销，也不能防止拥有 root/源码的人修改校验或时钟；后续在线租约应单独验证，避免授权服务故障影响基础营业。

## 干净环境构建

移动端原锁文件沿用 Vite 7.3.7，而 UniApp 插件 peer 声明固定为 Vite 5.2.8。本分支以项目 `.npmrc` 固定 `legacy-peer-deps=true`，保持原锁文件选择，并通过 H5 与微信小程序构建验证这一组合；未来升级 UniApp 时应重新核对官方兼容矩阵。

Node.js 22.13+；JDK 17；Maven。两个前端分别运行 `npm ci`。Windows 可使用原有构建命令；Linux 的 H5 构建使用 `UNI_INPUT_DIR=$PWD npx --no-install uni build -p h5`。

```text
delta-admin-ui: npm run build
delta-mp:      npm run build:h5（Windows）
delta-game:    mvn -pl delta-admin -am test
```

新增测试验证伪造/跨实例授权、模块到期、角色隔离、状态持久化，并使用独立运营后台签发的测试文件验证 Node.js → Java 互通。测试公钥不是生产公钥，未提交对应私钥。
