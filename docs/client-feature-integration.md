# 通用客户端：修复与授权接入

本分支基于 `cangshuo-detla/main`，与独立运营后台 `cangshuo-detla-authorize` 分开维护。没有复制 742 的品牌、Logo、域名、端口、运行数据、支付或短信凭据。

新增功能：公众号与业务短信四角色通知中心、客服上班过滤、两级退款审批、履约审核合并、访客与日活运营看板、PC/手机客服工作台、完整后台手机号、图片缓存与适配优化；本地 WebSocket 使用当前站点代理，配置整数校验和新库首次管理员引导继续保留。

## 接入运营中心

1. 从运营中心导出验证公钥，放入客户服务器私有配置目录。不要向客户服务器复制签发私钥。
2. 配置 `PLATFORM_CUSTOMER_ID`（与运营中心客户编号一致）、`PLATFORM_STATE_PATH`（可写且持久保存的实例状态文件）和 `PLATFORM_PUBLIC_KEY_PATH`（公钥文件路径）。未配置客户编号时显示 `unconfigured`，不能导入其他客户的授权。
3. 管理员在「功能与更新 → 功能商城」复制实例 UUID，将客户编号、实例编号、客户端版本和客户使用的域名交给运营人员登记。
4. 授权中心完成在线支付或人工收款后自动签发授权。客户端配置 `PLATFORM_REPORT_URL=https://授权中心域名/api/client/report` 后，会使用签名授权定期自动上报当前版本并同步授权。授权中心只控制授权有效期，客户端管理员自行决定功能是否实际启用。
5. 功能商城的购买和续费由客户端后端请求授权中心创建订单，客户端跳转到授权中心一次性收款页。支付金额由授权中心计算，微信商户密钥和支付回调不会下发到客户端。
6. 更新签发文件包含该实例当前有效模块的完整集合；签发与重复领取均由运营中心保证幂等。旧版单一有效期授权仍可验证。
7. 已由授权中心管理的付费模块，功能商城价格必须使用授权中心同步的 priceCents；授权中心暂未返回价格时显示人工报价，不得回退显示客户端内置历史价格。

此客户端文档对应正式版 `1.11.0`。现有商品、订单、钱包、提现、聊天、打手工作台和收益日报继续使用，基础业务不因更新收费。

## 资金结算与会员运营

- 订单确认后的打手收益先进入待结算金额，只有售后期结束、订单没有进行中的投诉或退款时才转为可提现余额。
- 售后观察期由后台 `结算配置 > 订单收益售后观察期` 控制，默认 72 小时，可设置为 0 至 720 小时。
- 退款优先冲减待结算收益，不会先把收益放进可提现余额；结算失败由后台任务自动重试并记录失败原因。
- 提现收款人必须与已通过实名认证或入驻真实姓名一致；可在 `提现配置 > 提现校验收款人实名` 中控制。
- 用户可收藏商品、关注打手，在「我的 > 收藏与关注」统一查看；历史订单可再次下单并带出原始填写信息。
- 管理员账号删除采用归档保留。新增或编辑时复用已删除账号的用户名，会先把旧记录重命名为不可登录的归档名，再创建新的独立账号，避免旧登录身份被恢复。
- 管理员与客服统一从后台域名登录。PC 使用 `/login`、`/dashboard`；手机使用明确的 `/h5/login`、`/h5/dashboard`，不再按窗口宽度自动跳转；公众号绑定页为 `/h5/wechat-binding`。`/mobile` 已不再注册为页面，仅保留静态兼容分流；旧公众号回调配置会自动迁移到 `/h5/wechat-binding`。客户 H5 的旧 `/pages-cs/login/index` 只做兼容跳转，实际后台地址由 `site.staff_web_url` 配置。绑定必须在微信内置浏览器完成，管理员和客服分别保存公众号 OpenID。
- 公众号模板按客户、打手、管理员和客服分别配置。角色模板组优先于旧版通用模板；管理员和在线客服会在订单支付、接单和完成节点收到对应角色的独立模板。
- API 中的角色分别对应 `USER`、`PLAYER`、`ADMIN`、`CS`。旧角色 `BOTH` 按最高权限 `ADMIN` 处理，不再新增另一套超级管理员账号。
- 业务短信按客户、打手、管理员、客服分别填写模板 Code 和变量映射，事件组与公众号一致；阿里云模板需要先在供应商后台审核。
- 订单支付成功才算有效新订单。未指定打手时，向所有在线正常打手发送；没有任何在线打手时，向所有正常状态打手发送并明确注明当前暂无打手在线。
- 当班客服状态只影响客服账号；`ADMIN` 始终接收运营通知。未上班客服不会收到订单、投诉、退款和人员审核通知。
- 公众号与短信任务分别记录。已知失败按上限重试，投递结果未知时停止自动重发，等待管理员确认后手动重试。终态记录保留 30 天。
- 公众号和短信的每个角色都提供五类事件的直接填写表单、官方字段限制、最终通知预览和自动生成配置，无需手工编辑 JSON。
- 公众号配置按微信当前官方字段类型校验；发送接口支持可选的网页跳转、小程序跳转，并自动生成防重复 `client_msg_id`。
- 通知配置指南会逐项解释每个字段，并给出公众号后台、阿里云短信后台的填写步骤、平台模板正文、最终通知预览和可直接复制的八份 JSON。

## 退款、售后与审核

- 客户或客服提交退款申请；客服只能开始核验并提交初审建议，`ADMIN` 终审通过后才调用支付渠道退款。
- 同一订单同时只能存在一个活动退款。请求支持客户端幂等号，最终状态包含已退款、失败、管理员驳回和已拒绝。
- 客户退款接口只返回客户可见字段；客服备注、管理员备注、审核人员 ID、投诉来源 ID 和支付渠道内部退款号仅出现在后台接口。
- 投诉仲裁生成的退款进入同一审批链。退款成功时关闭投诉；`ADMIN` 驳回退款时同步关闭投诉并恢复订单结算，避免卡在 `ARBITRATED`。
- PC 端接力与换人合并到「履约审核」入口；手机端支持客服退款初审、履约审核及按审核类型筛选待办。
- 管理员和客服在订单列表、详情中直接查看完整客户手机号；用户端和打手端不得读取其他人的手机号。

## 运营看板

- 管理端展示今日访客、登录日活、新增用户、订单、有效订单、成交额、退款、完成订单、今日/昨日对比和 7/30 天趋势。
- 订单漏斗从访问、提交订单、有效订单到完成订单；在线、离线、冻结打手及当班客服人数可查看。
- 在线/离线/冻结打手人数支持下钻查看具体人员、等级、进行中订单和最后在线时间，不返回手机号或实名信息。
- 匿名访客键与设备摘要使用 HMAC，不保存原始 IP 或 UA 明文。

## 手机端客服与管理员后台

- 工作台采用卡片式分组：首屏优先显示待办、今日订单数据和在线/离线打手，随后展示商品、业务办理、人员与客户、消息与审核入口。
- 管理员和客服共用操作组件，但页面标题、客服排班控制和功能入口按登录角色及权限动态区分。
- 待办、审核中心已经覆盖的页面会从业务快捷入口中自动排除；同一导航不重复展示，已在测试中持续校验。
- “待确认订单”直接打开 `COMPLETED` 状态订单，提现审核独立进入资金审核；人员审核、素材审核与履约审核集中到审核中心。
- 待指派订单从工作台进入后直接落到待派单筛选；订单卡显示完整客户电话并支持拨号。
- 派单页默认显示在线可派单打手，可切换到全部打手；在线状态、当前接单量和满载状态在同一卡片中展示。
- 订单详情固定底部操作区，客户电话和拨号入口位于页面顶部，返回详情时自动刷新订单状态。
- 电脑管理后台在微信和手机窄屏打开时同样使用专用卡片工作台，不再直接压缩桌面表格；顶部为单行导航，底部提供工作台、订单、待办和菜单入口。
- 管理后台手机工作台直接展示今日待办、访客、登录日活、有效订单、收款及在线/离线/冻结打手；打手人数可下钻，业务入口继续按角色权限过滤。
- 手机端不再显示左上角菜单和移动侧栏；所有可访问功能按客户、订单、人员、财务、内容和系统分组直接排列在工作台，未授权路由不会生成入口。
- 列表页在手机端自动按表头转换为卡片；订单号、手机号、金额、状态、时间和操作不会再被压缩在桌面宽表里。

## 后台批量操作

- 商品列表支持批量上架、下架、调整分类、统一设置价格、按比例调整价格、复制为下架草稿和删除。商品批量修改使用整体事务，任一选中商品失效时不会只改成功一部分。
- 用户列表支持批量恢复正常、封禁和删除。系统继续执行余额、资金流水、未完成支付、订单及关联打手校验；失败项会在结果提示中列出。
- 打手列表支持批量审核通过、驳回、调整等级和解冻。审核、冻结与等级授予由服务端校验原状态，停用等级不能用于批量分配。
- 批量栏只在勾选数据后出现；查询、翻页、切换筛选和完成操作后会自动清空选择，避免把当前页选择误用到其他列表。

## 初次管理员引导

新库可显式设置 `BOOTSTRAP_ADMIN_ENABLED=true`、`BOOTSTRAP_ADMIN_USERNAME`、`BOOTSTRAP_ADMIN_PASSWORD`。仅在管理员表为空时创建账号，已有账号不重置。创建后应关闭引导开关。

## 数据与发布边界

- 保留主库原有迁移脚本和部署资料。不要把仓库内旧种子数据重新导入正在运行的客户数据库。
- 新增 `phone_unique` 的迁移只修复结构；上线前先检查重复手机号并完成备份，不自动清除用户记录。
- 授权状态文件应与客户数据库、配置和上传文件一起纳入备份。删除状态文件会改变实例 UUID，需要重新登记签发。
- 系统更新页从授权运营中心读取正式版目录，按后端、管理后台和 H5 的实际组件版本判断缺口，支持选择非必要更新项及依赖项；服务端计算更新计划、校验正式包，并在执行前备份。
- GitHub 正式版本发布后，由发布方通知客户。客户自行登录所属项目的管理后台，选择更新内容并启动更新；内部维护人员不代客户点击，也不直接替换线上客户端。更新完成后核验组件版本和本地健康检查，失败时使用更新备份回退。授权运营中心不直接登录客户业务后台执行安装。
- 离线授权不能即时撤销，也不能防止拥有 root/源码的人修改校验或时钟；后续在线租约应单独验证，避免授权服务故障影响基础营业。

## 干净环境构建

移动端原锁文件沿用 Vite 7.3.7，而 UniApp 插件 peer 声明固定为 Vite 5.2.8。本分支以项目 `.npmrc` 固定 `legacy-peer-deps=true`，保持原锁文件选择，并通过 H5 与微信小程序构建验证这一组合；未来升级 UniApp 时应重新核对官方兼容矩阵。

Node.js 22.13+；JDK 17；Maven。两个前端分别运行 `npm ci`。Windows 可使用原有构建命令；Linux 的 H5 构建使用 `UNI_INPUT_DIR=$PWD npx --no-install uni build -p h5`。

```text
delta-admin-ui: npm run build
delta-mp:      npm run build:h5（Windows）
delta-game:    mvn -pl delta-admin -am test
```

新增测试验证伪造/跨实例授权、模块到期、角色隔离、状态持久化，并使用独立运营后台签发的测试文件验证 Node.js → Java 互通。测试公钥不是生产公钥，未提交对应私钥。
