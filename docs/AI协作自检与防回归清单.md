# AI 协作自检与防回归清单

更新日期：2026-11-13。适用于 Delta 产品主线及授权中心；规则层级遵循 [VIBE_CODING.md](VIBE_CODING.md)。本清单记录已经暴露的失误和对应检查，不代表这些检查在每次任务中都已通过。

## 1. 开工先确认事实

- 先读四份必读文档，再读本清单；记录实际工作目录、分支、HEAD、未提交改动和本次目标端。`delta-mp` 同时承载客户 H5，不能看到目录名就把任务当成小程序。
- 当前需求和最新纠正优先。用户说“用户 H5”“管理端移动端”“PC 手机自适应”时，先对应域名、路径、角色和布局；后台 `/h5` 与用户 H5 是不同应用入口。
- 多 worktree 时核对 `git worktree list`、规则版本与发布提交。常用目录可能停在旧开发分支；隔离工作区的新规则不能只留在那里。仅同步已核对的规则与索引，不覆盖用户源码、不 reset、不清理陌生文件。
- 摘要、旧报告和定时监控提示只是线索，不能代替当前代码、日志或生产证据。插入的监控任务只执行其只读范围，不挤掉用户正在推进的主任务。
- 用户已授权的工作持续做完；保留既有确认门槛。缺少不可替代的信息时才询问，等待期间继续独立工作；不能把未回复当作同意。

## 2. 修复必须覆盖业务闭环

先建立“复现条件 → 证据 → 根因 → 影响范围 → 修复 → 验证”的记录。未定位原因时写明假设，不把猜测写成定论。

| 曾遗漏的问题 | 每次相关改动必须检查 |
| --- | --- |
| 能进入页面就宣称全面验收 | 从实际路由清单列出页面；逐项区分路由加载、界面操作、业务闭环。403 只证明权限拒绝生效，不算该功能验收。截图、控制台、网络错误和主要操作结果共同判断 |
| 后端已有功能，后台没有入口或无法保存 | 检查菜单、PC/H5 路由、角色权限、表单、提交、回读、开关关闭/无授权/过期状态、失败提示；后端独立校验权限 |
| 首页堆积卡片，“我的”页臃肿 | 按用户任务安排信息优先级。保留运营入口在用户 H5“我的”、最近购买悬浮滚动的既定决定；检查长文本、空数据、底栏遮挡、返回及刷新后的状态 |
| PC 手机布局与后台 H5 混淆 | 分别检查 PC 宽屏、PC 窄屏、后台 `/h5`；不按屏宽自动跳转。直接深链、站内前进/返回、浏览器返回、401/403/404 都须有合理去向 |
| 手机支付成功，电脑没有刷新 | 验证二维码生成、微信回调页、支付调起、取消/失败/成功、电脑轮询后关闭二维码并跳转；页面卸载应清理轮询。模拟回调与真实微信支付分别标记，不代用户付款 |
| 微信支付卡在“正在调起” | 核对实际响应 CSP、回调脚本执行、SDK 请求和出口网络。保留已部署的回调专用 CSP 与 `-Djava.net.preferIPv4Stack=true`；禁止为修回调而全站放宽 CSP |
| 修了图片路径，漏了租户缓存 | 同时查域名租户、旧/新路径、原图/缩略图、目录边界、缓存键、前端 URL 生成；用 A/B/A 相同相对路径验证不串图，另测跨租户拒绝和不存在文件 404 |
| 图片/JS 200，实际返回 HTML | 公网验证状态码、MIME 和实际内容；检查动态 import、中文文件名、缓存入口和缺失资源 404。执行静态引用检查，不能只检查首页 |
| 配置乱码 | SQL 会话显式 utf8mb4，中文使用 UTF-8 文件；保存后回读并核对页面。不能以扩大乱码替换规则掩盖错误写入 |
| 删除账号后不能再注册，删除打手漏查收益 | 检查身份释放、旧 Token 失效和历史业务归属；打手删除包含余额、待结算收益、订单、提现、投诉和追回债务。禁止为通过测试清零客户资金 |
| 主题提示已授权，启用却报域名错误 | 检查授权中心权益、本地开关、请求 Host、前端可见状态和启用/停用结果，不能仅凭商品卡片验收 |
| 后台审核看不到打手提交的申请资料 | 申请资料按实体字段逐项呈现：真实姓名、手机号、游戏ID/段位、擅长服务、技能标签、证明截图、押金单号和提交时间；图片可放大核对。PC 后台与工作人员 H5 复用同一组件时两端同时验证 |
| 一键通过入驻审核，没有二次提示 | 通过前展示申请人摘要和可选等级，确认后才调用接口；驳回必须填写原因并显示申请人名称。批量审核逐项回报成功和失败原因 |
| 在落后主线的旧 worktree 改代码，构建缺模块 | 开工先比对 HEAD 与 main、catalog 版本和 git worktree list；发现工作区落后时在最新 worktree 修改。旧目录未提交源码保留，两套目录不得各改一半再混用 |

同类问题横向检查 JAX、742、747 及相关管理 PC、管理 H5、客户/打手 H5。只验证一个租户时，结论只能覆盖该租户；通用代码相同不代表各租户配置、文件和数据状态相同。

浏览器移动宽度、WebKit 模拟、iOS/Android 真机、微信/QQ 内置浏览器分别记录。没有真机条件写“未验证”，不可用 UA 或截图模拟声称真机通过。

## 3. 执行工具时避免重复失误

- PowerShell 不嵌入复杂 Bash，尤其是 `$()`、反引号、重定向、SQL 和多层引号。远程多行命令先写到 D 盘任务目录的 UTF-8/LF `.sh`，检查内容后通过现有工具上传再执行；上传与执行必须在当前授权范围内。只读任务不得借此写入或修改远程配置。
- 命令超时或输出中断时，先检查会话、进程和目标状态，不直接重复变更操作。长任务用可轮询会话，给出有意义的进展。
- Java 流/ZIP 使用 try-with-resources；Python 文件使用 `with`；测试结束释放文件、服务和连接。Windows 临时目录删除失败也是待修问题，不隐藏、不篡改测试计数。
- HTTP 超时先区分 DNS/CDN、IPv4/IPv6、代理、源站和本地工具。用独立路径复核；源站 `--resolve` 成功不等于公网正常，单一路径超时也不能直接认定服务宕机。
- 记录验收主动产生的负向请求和时间段。预期跨租户 404 与合法资源 404 分开统计；PAYING 数量与财务违规数分开判断。

## 4. 测试证据对应最终改动

- 保存工作目录、commit/变更范围、命令、环境、时间、退出码与实际输出。通过数、失败数、跳过数只取最终报告；旧发布的计数不能复制成本次结果。
- 最后一次代码、测试或运行配置变更后，重跑受影响验证；正式发布前跑约定的全量套件和构建。仅改说明文字不重跑业务套件、不升软件版本。没有新改动或失败，不反复跑已通过的重型检查。
- 单测、源码契约检查、构建、浏览器操作、生产验收是不同证据。全页面验收须有“租户/角色/路由/环境/操作/预期/实际/证据/未验证原因”清单，不能用路由数量代替功能完成度。
- 安全相关修复覆盖正常与拒绝路径；资金改动覆盖金额、幂等、并发和状态流。修好当前复现后再查同类调用点，避免只补一个页面。

## 5. 发布与收尾

- 先识别部署形态：JAX/742/747 走共享服务组签名计划；独立实例保留客户最终点击。按 [共享服务组规则](共享服务组更新入口与发布规则.md) 执行，不因实例页提示而启动旧执行器。
- 发布证据覆盖制品 commit/摘要、备份与审计、容器、三个组件版本、公网域名/API/静态资源、业务关键路径、负向权限、逐租户数据库/财务、授权上报和最近日志。容器 healthy 不是业务验收。
- 收尾用 `rg` 检查本次涉及的入口、现状表和索引中的旧版本、旧计划、“尚未升级”等表述；逐条区分历史与现状，不全仓替换历史版本号。历史结论必须带日期，状态变化补新记录。
- 更新 VIBE 版本时同步主仓库、隔离工作区、全局和客户/授权中心 AGENTS 入口。运行 `python deploy/qa/check_collaboration_rules.py`；本机用重复的 `--entry <AGENTS绝对路径>` 检查外部入口回执。CI 只检查检出的仓库。
- 最终报告实际改动、实测结果、未测项和必要观察项；不把“已写代码”“已发布”“已部署”“已验收”混为一谈。不要声称能修改模型本身或保证永不犯错。

此检查脚本只检查入口、回执、链接、冲突标记与编码损坏，不能证明 AI 理解了规则，也不能替代业务或安全验收。新失误优先补进对应条目及有价值的回归检查，不堆叠重复口号。
