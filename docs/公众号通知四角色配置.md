# 公众号通知四角色配置

公众号通知支持客户、打手、管理员、客服四种独立模板。不同角色可以使用不同微信公众号模板，也可以复用同一个微信模板 ID，但字段映射必须与角色实际收到的内容一致。

完整说明见[公众号与业务短信配置指南](通知模板完整示例.md)。配置页已经改成直接填写模板 ID、模板变量和系统数据源，不需要手工编写 JSON。

## 后台位置

「系统管理 → 系统配置 → 公众号通知」：

| 配置项 | 角色 |
|---|---|
| 客户专属模板组 | 普通用户、游客客户 |
| 打手专属模板组 | 接单员 |
| 管理员专属模板组 | 管理员 |
| 客服专属模板组 | 客服 |

每个角色包含以下事件，可在页面中分别启用和填写：

- `new_order`：有效新订单
- `order_status`：支付、指派、接单、开始服务、完成和确认；退款成功统一走 `refund_status`，未支付取消只保留客户站内提醒
- `refund_status`：退款申请、初审、终审、执行中、成功、失败、驳回
- `complaint_status`：投诉提交、申诉、退款待终审和处理结果
- `staff_review`：打手入驻审核、主页素材审核、冻结和解冻

每个事件直接填写微信模板 ID 和参数。模板变量左侧填写公众号模板中的变量前缀，例如 `thing1`；右侧选择系统数据。推荐字段为：

- `thing1`：`status`
- `character_string2`：`orderNo`
- `amount3`：`amount`
- `thing4`：`customerName`
- `thing5`：`playerName`
- `time6`：`time`

当前官方发送接口不再把旧版 `phrase` 列为主要字段类型。新模板应使用 `thing`、`character_string`、`time`、`amount`、`phone_number`、`car_number` 或 `const`，具体限制以配置页的官方字段说明为准。

字段值只能使用：`message`、`status`、`time`、`orderNo`、`amount`、`customerName`、`playerName`。其中客户名和打手名用于“谁给谁接单”的独立字段，不要求把完整手机号写入消息正文。

## 业务短信角色模板

「短信配置」中同样为客户、打手、管理员、客服分别填写模板 Code 和参数：

- 客户业务短信模板组
- 打手业务短信模板组
- 管理员业务短信模板组
- 客服业务短信模板组

模板 Code 从阿里云审核通过的短信模板中复制。左侧变量名必须与 `${变量名}` 一致，例如 `orderNo/status/customer/player`；右侧选择系统支持的数据源。短信侧事件同样为 `new_order`、`order_status`、`refund_status`、`complaint_status`、`staff_review`。

## 角色建议

- 客户模板突出“订单状态、订单号、处理时间”。
- 打手模板突出“指派/接单、审核结果、提现结果”。
- 管理员模板突出“新订单、异常处理、待确认事项”。
- 客服模板突出“新订单待接待、接单后跟进、完成待确认”。

素材审核和提现审核通常没有订单号，不建议映射 `orderNo` 和 `amount`。

## 绑定

- 客户：用户端「我的 → 公众号消息通知」。
- 打手：接单员中心「我的 → 公众号消息通知」。
- 管理员、客服：在微信内打开当前客户域名下的 `/#/pages-cs/login/index`，使用各自后台账号登录，再进入「我的 → 公众号消息通知」。

绑定必须在微信内置浏览器完成，并且所有接收人应先关注配置的公众号。
