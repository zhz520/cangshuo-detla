# 1.4.4 微信公众号支付配置教程

适用对象：客户后台管理员、项目运维人员、对接公众号和微信支付的技术人员。

最后核对日期：2026-11-02。

本文所说的“公众号支付”，对应微信支付官方产品中的“JSAPI 支付”：用户在微信内置浏览器访问客户 H5 页面，后端以公众号 AppID 取得同一个公众号下的 OpenID，再创建 JSAPI 支付并调起微信收银台。

官方平台上的具体开通、域名、授权目录和密钥获取步骤，请同时阅读：[微信支付商户平台配置教程](./微信支付商户平台配置教程.md)。

## 先确认这 8 件事

1. 公众号通常是已认证的服务号，或微信支付官方允许的政府、媒体类型公众号；AppID 已与商户号绑定并开通 JSAPI 支付权限。微信官方对 JSAPI AppID 的资格和绑定有明确要求，见[开发接入准备（JSAPI 支付）](https://pay.wechatpay.cn/doc/v3/merchant/4015423216)。
2. 已取得微信支付商户号、公众号 AppID、公众号 AppSecret、商户 API 证书私钥、商户证书序列号、APIv3 密钥、微信支付公钥及公钥 ID。
3. 客户站点已启用 HTTPS，证书链完整，域名可被微信客户端和微信支付服务器正常访问。
4. 国内服务器的站点域名已按实际经营要求完成 ICP 备案。支付授权目录要求使用已备案域名，不能填写 IP。
5. 公众平台的“网页授权域名”与商户平台的“支付授权目录”已经分别配置。两处不是同一项设置，也不能互相代替。
6. 小程序、公众号是两个不同的 AppID 和 OpenID 命名空间。不能用小程序 OpenID 发起公众号支付，也不能反过来混用。
7. JSAPI 支付只能从微信内置浏览器发起。手机系统浏览器、桌面浏览器、普通 App WebView 应分别使用项目支持的其他支付方式。
8. 正式配置前已备份数据库、证书、支付参数和反向代理配置；配置期间先关闭全局支付开关，完成后再做小额真实交易验证。

## 支持的支付方式

授权运营中心的微信支付方式固定为以下 5 项：

| 授权中心方式 | 用途 | 发起环境 | 关键约束 |
| --- | --- | --- | --- |
| H5 | 手机站外部浏览器支付 | 微信外的主流手机浏览器 | 不能当作公众号支付使用，最终可用性以商户号 H5 支付权限和客户端适配为准 |
| JSAPI（小程序） | 小程序内支付 | 微信小程序 | 使用小程序 AppID 与 wx.login 等小程序链路取得的小程序 OpenID |
| OFFICIAL（公众号） | 微信内置浏览器 H5 支付 | 微信客户端内置浏览器 | 官方名称是 JSAPI 支付；使用公众号 AppID 和公众号网页授权取得的公众号 OpenID |
| NATIVE | 二维码扫码支付 | PC 页面等 | 需要生成二维码和查单、回调闭环，配置完成不等于客户端已具备扫码界面 |
| APP | 原生 App 支付 | iOS、Android App | 使用移动应用 AppID；不能把 JSAPI 参数直接交给原生 App |

后台保存了支付方式，只表示授权中心允许该项目选择该方式。客户端是否真正可用，还取决于公众号、小程序、网站或 App 的接入状态、商户权限，以及项目程序是否完成对应支付链路。

## 配置键

在客户管理后台进入“系统管理 → 系统配置 → 微信支付配置”，按当前版本的配置项保存。以下键名是固定配置键。

| 配置键 | 用途 | 建议值与注意事项 |
| --- | --- | --- |
| wx.pay.enabled | 微信支付总开关 | 初次配置保持 false；完成全部材料和联调后再设为 true |
| wx.pay.miniapp-enabled | 小程序支付开关 | 仅在客户端确实通过小程序支付时开启 |
| wx.pay.h5-enabled | 手机 H5 支付开关 | 用于微信外手机浏览器；不是公众号支付开关 |
| wx.pay.official-enabled | 公众号支付开关 | 仅当公众号 AppID、AppSecret、回跳 Origin、商户绑定和授权目录全部就绪时开启 |
| wx.pay.appid | 现有通用或小程序支付 AppID | 保留现网已验证原值；小程序支付时通常是该小程序 AppID。不要改成新加的公众号 AppID |
| wx.pay.official-appid | 公众号 AppID | 从公众平台“设置与开发 → 开发接口管理 → 基本配置”取得，必须与商户号绑定 |
| wx.pay.official-appsecret | 公众号 AppSecret | 只在服务端使用；禁止出现在前端、截图、工单、代码仓库和普通日志中。泄露后立即重置 |
| wx.pay.official-return-origin | 公众号支付回跳站点 Origin | 必须是完整 HTTPS 站点源，例如 https://pay.example.com；只能包含协议和域名，正式环境使用默认 443 端口，不能含路径、查询参数、锚点或用户信息 |
| wx.pay.mch-id | 微信支付商户号 | 使用已绑定公众号 AppID 的商户号，必须与商户证书、APIv3 密钥和公钥属于同一商户 |
| wx.pay.notify-url | 支付结果通知地址 | 公网可访问的完整 HTTPS 地址，例如 https://pay.example.com/api/pay/wx/notify；不能带查询参数 |
| wx.pay.refund-notify-url | 退款结果通知地址 | 公网可访问的完整 HTTPS 地址，例如 https://pay.example.com/api/pay/wx/refund-notify；不能使用内网地址 |
| wx.pay.api-v3-key | APIv3 密钥 | 32 个字符；用于回调报文解密。它不是 APIv2 密钥，也不是商户私钥 |
| wx.pay.cert-serial-no | 商户 API 证书序列号 | 必须与上传的 apiclient_key.pem 来自同一份商户 API 证书 |
| wx.pay.private-key-path | 商户 API 证书私钥文件 | 在后台上传 apiclient_key.pem 或对应私钥文件，由系统生成服务器路径；不要填电脑本地路径 |
| wx.pay.public-key-id | 微信支付公钥 ID | 通常以 PUB_KEY_ID_ 开头；必须与上传的微信支付公钥匹配 |
| wx.pay.public-key-path | 微信支付公钥文件 | 在后台上传从商户平台下载的 pub_key.pem，由系统生成服务器路径 |

### 最容易混淆的字段

| 字段 | 用途 | 不能拿来替代 |
| --- | --- | --- |
| 公众号 AppID | JSAPI 下单、网页授权、调起支付使用 | 小程序 AppID、开放平台移动应用 AppID |
| 公众号 AppSecret | 服务端 code 换 OpenID | 小程序 AppSecret、AppSecret 不能放前端 |
| 商户 API 证书私钥 | 给商户 APIv3 请求签名 | 微信支付公钥、APIv3 密钥 |
| 商户证书序列号 | 标识商户签名证书 | 微信支付公钥 ID |
| APIv3 密钥 | 解密微信支付回调 | 公众号 AppSecret、商户私钥 |
| 微信支付公钥 | 验证微信支付应答和回调签名 | 商户 API 证书或其私钥 |
| 微信支付公钥 ID | 选择正确的微信支付公钥 | 商户证书序列号 |

## 建议的域名与路径规划

假设客户站点的公网支付域名是 https://pay.example.com，当前项目在配置正确时会按下列路径工作：

| 事项 | 示例 | 配置位置 |
| --- | --- | --- |
| 公众号网页授权域名 | pay.example.com | 公众平台 → 设置与开发 → 公众号设置 → 功能设置 → 网页授权域名 |
| 公众号支付回跳 Origin | https://pay.example.com | 后台配置键 wx.pay.official-return-origin |
| 网页授权回调页 | https://pay.example.com/api/pay/wx/official/callback | 由系统按 Origin 生成，无需在配置键里另填路径 |
| 支付授权目录（精确到模块） | https://pay.example.com/api/pay/wx/official/ | 商户平台 → 产品中心 → JSAPI 支付/开发配置 → 支付授权目录 |
| 支付授权目录（整个站点） | https://pay.example.com/ | 同上；会覆盖该域名的全部页面，选择范围更大 |
| 支付结果通知 | https://pay.example.com/api/pay/wx/notify | 后台配置键 wx.pay.notify-url |
| 退款结果通知 | https://pay.example.com/api/pay/wx/refund-notify | 后台配置键 wx.pay.refund-notify-url |

支付授权目录必须与微信内置浏览器实际加载并调起支付的页面 URL 一致，包括 HTTPS、域名、大小写以及多级目录；且必须以“/”结尾。精确到模块通常比整站配置更安全。微信官方规则见[配置 JSAPI 支付授权目录](https://pay.wechatpay.cn/doc/v3/merchant/4013287088)。

如果客户使用反向代理，必须保证上述域名在微信客户端、微信支付服务器都能公网访问，并正确转发到后端端口。不要只验证“浏览器能打开”，还要验证从外部网络访问支付授权目录和两个通知路径。

## 授权运营中心如何填写

在授权运营中心进入微信支付设置，先开启微信支付通道，再按项目实际能力勾选 H5、JSAPI（小程序）、OFFICIAL（公众号）、NATIVE、APP。只勾选已经接入并测试过的方式。

| 授权中心字段 | 应与客户后台保持一致 |
| --- | --- |
| appId | 客户后台 wx.pay.appid，也就是现有小程序或通用支付 AppID |
| officialAppId | 客户后台 wx.pay.official-appid |
| officialAppSecret | 客户后台 wx.pay.official-appsecret，属于高敏感凭据 |
| officialReturnOrigin | 客户后台 wx.pay.official-return-origin，例如 https://pay.example.com |

授权中心保存的是通道和能力声明，不会替客户自动开通微信侧权限，也不应在实例项目声明中下发 AppSecret。实际 OpenID、证书、APIv3 密钥和商户密钥都只由客户后端使用。

项目维护期到期或授权停用后，应按授权中心的策略暂停业务；支付回调仍需以服务端验签、交易查询和本地台账为准，不能因为前端页面失效就假定已成交或未成交。

## 配置顺序

### 第 1 步：在公众平台完成公众号准备

1. 登录微信公众平台。
2. 进入“设置与开发 → 公众号设置 → 功能设置”。
3. 找到“网页授权域名”，下载校验文件。
4. 将校验文件原样放到该域名根目录，确认通过 HTTPS 可直接访问。
5. 填写完整域名，不带 https://、路径或端口。例如只有 pay.example.com。
6. 保存并确认平台显示成功。开启强制 HTTPS 校验时，站点必须先有有效证书。
7. 到“设置与开发 → 开发接口管理 → 基本配置”核对公众号 AppID。
8. 在服务端安全取得或重置 AppSecret。不要通过聊天工具传递完整密钥。

微信官方将网页授权域名与支付授权目录作为两项独立配置；支付文档也明确指出，只配置支付授权目录时仍无法取得 OpenID，见[JSAPI 支付开发指引](https://pay.wechatpay.cn/doc/v3/merchant/4012791870)。

### 第 2 步：在商户平台完成产品、绑定和支付目录

1. 登录微信支付商户平台。
2. 在“产品中心 → JSAPI 支付”确认产品权限已开通。
3. 在“产品中心 → AppID 账号管理 → 关联 AppID”提交公众号 AppID。
4. 回公众平台确认该商户号绑定。
5. 在“产品中心 → JSAPI 支付/开发配置 → 支付授权目录”添加上表中的实际支付目录。
6. 等待平台生效，一般约 5 分钟；不要频繁重复添加相同目录。

### 第 3 步：在客户后台填写非敏感配置

1. 先保持 wx.pay.enabled = false。
2. 填写 wx.pay.appid 的原有正确值，不要用公众号 AppID 覆盖。
3. 填写 wx.pay.official-appid、wx.pay.official-appsecret 和 wx.pay.official-return-origin。
4. 填写 wx.pay.mch-id。
5. 填写两个通知地址。地址必须是完整、公网可达、无查询参数的 HTTPS URL。
6. 按需求开启 wx.pay.miniapp-enabled、wx.pay.h5-enabled、wx.pay.official-enabled；首次联调建议只开启公众号支付。

### 第 4 步：上传商户证书和微信支付公钥

1. 在商户平台申请或查看商户 API 证书，取得 apiclient_key.pem 和对应证书序列号。
2. 在客户后台上传私钥文件，填入证书序列号。不要把私钥粘贴到普通文本配置项。
3. 在商户平台 API 安全页面申请或下载微信支付公钥，取得 pub_key.pem 和以 PUB_KEY_ID_ 开头的公钥 ID。
4. 在客户后台上传公钥文件，填入公钥 ID。
5. 设置 32 字符 APIv3 密钥。该值在商户平台设置后通常不能再次明文查看，必须由授权人员存入服务器密钥管理或后台加密字段。
6. 保存后检查文件路径由系统生成，文件权限只允许应用运行账号读取。

### 第 5 步：开启并做小额验证

1. 将 wx.pay.official-enabled 设为 true，再解除 wx.pay.enabled 的关闭状态。
2. 在授权中心只启用 OFFICIAL（公众号），不要同时勾选尚未验收的方式。
3. 用微信扫描测试公众号入口或从公众号菜单进入支付页。
4. 使用真实的 0.01 元至 0.10 元商品测试；这是正式微信支付交易，会产生真实扣款，完成后按流程退款。
5. 核对订单创建、网页授权、OpenID、预支付、收银台、支付回调、订单状态和退款通知。
6. 通过后再逐个开启小程序、H5、NATIVE 或 APP。

## 公众号支付链路

1. 用户在微信内置浏览器进入客户 H5 订单页。
2. 客户端调用公众号支付接口，后端创建待支付记录并生成一次性 state。
3. 后端跳转到微信网页授权地址，scope 固定为 snsapi_base；它静默授权，只用于取得 OpenID，无需读取昵称头像。
4. state 必须由服务端随机生成、限时保存、一次使用，并绑定支付单号和用户，不能直接信任前端回传值。
5. 微信回调到 https://公网域名/api/pay/wx/official/callback，并携带 code 和 state。
6. 后端校验 state，再用公众号 AppID、AppSecret 和 code 调用微信接口换取 OpenID。code 只使用一次，不能写日志。
7. 后端使用同一个公众号 AppID、商户号、通知地址和公众号 OpenID 创建 JSAPI 预支付单。
8. 页面通过微信内置的 WeixinJSBridge 调起支付。前端回调只用于界面跳转，不能作为财务到账依据。
9. 微信支付服务器把支付结果通知发送到 wx.pay.notify-url；后端验签、用 APIv3 密钥解密、核对 AppID、商户号、币种、金额、支付单号和交易号后，以幂等方式更新交易。
10. 如通知延迟或未到，必须主动查单；退款是否成功也必须以退款通知或查单结果为准。

snsapi_base 的官方说明是可静默取得 OpenID，流程到换取网页授权 access_token 和 OpenID 结束，见[微信网页开发/网页授权](https://developers.weixin.qq.com/doc/service/guide/h5/auth.html)及[code 换网页授权凭证与 OpenID](https://developers.weixin.qq.com/doc/service/api/webdev/access/api_snsaccesstoken.html)。

## 公众号 OpenID 不能与小程序 OpenID 混用

同一个自然人可能在小程序、公众号和不同公众号中获得不同的 OpenID。OpenID 必须与本次下单使用的 AppID 成对保存和使用。

| 场景 | AppID | OpenID 取得方式 | 常见错误 |
| --- | --- | --- | --- |
| 公众号支付 | wx.pay.official-appid | snsapi_base 网页授权 | 拿小程序 OpenID 下单 |
| 小程序支付 | wx.pay.appid（小程序场景） | 小程序登录和 code2Session 等链路 | 拿公众号 OpenID 下单 |
| H5 支付 | 商户号允许的 H5 接入 AppID | 按 H5 支付产品链路 | 把 H5 支付当作公众号支付 |
| APP 支付 | 移动应用 AppID | 原生 App SDK 链路 | 把 JSAPI 签名参数交给 App |

建议数据库按“支付场景 + AppID + OpenID”保存，不要只有一个没有 AppID 上下文的 openid 字段。不要把 UnionID 当作支付 OpenID 的替代品。

## 上线前检查

- 公众号网页授权域名已生效，回调页能收到 code 和 state。
- 回调页地址的协议、域名与公众平台配置完全一致。
- 支付授权目录与用户实际发起支付的页面 URL 完全一致；若精确到目录，当前 1.4.4 的公众号支付目录通常是 https://支付域名/api/pay/wx/official/。
- 公众号 AppID 已与商户号绑定。
- JSAPI 支付产品权限已开通。
- 微信内、微信外、小程序三个入口没有互相串用 OpenID。
- 两个通知地址均为公网 HTTPS，无查询参数，能绕过登录鉴权并正确处理 POST。
- 反向代理没有吞掉签名请求头，没有缓存 POST，没有改写请求体。
- 通知接口能在 5 秒内返回成功，并支持重复通知的幂等处理。
- APIv3 密钥长度为 32 字符，私钥、证书序列号和公钥 ID 来自同一商户。
- 支付成功后金额和订单归属正确；退款申请、退款回调、对账都能闭环。
- 日志已脱敏 AppSecret、code、APIv3 密钥、私钥、OpenID 和完整签名串。

## 常见错误与排查

| 现象或错误 | 优先检查 |
| --- | --- |
| 10003：redirect_uri 域名与后台配置不一致 | 公众平台网页授权域名、Origin 域名、OAUTH 回调域名三者是否完全一致 |
| 10005：公众号没有相应 scope 权限 | 公众号类型、认证状态和网页授权能力是否符合要求 |
| 当前页面的 URL 未注册 | 商户平台支付授权目录是否与微信内置浏览器实际页面 URL 的协议、域名、目录和大小写完全一致 |
| JSAPI 支付必须传 openid | 后端是否完成 snsapi_base 授权并以本次公众号 AppID 换取 OpenID |
| 下单账号与支付账号不一致 | 发起授权的公众号 AppID、下单 AppID 和页面实际 AppID 是否同一个 |
| 拿小程序 OpenID 却支付失败 | 是否把小程序 OpenID 用在公众号 AppID 的 JSAPI 下单 |
| 该商户暂不支持通过外部拉起微信完成支付 | 当前是否在微信内置浏览器；外部浏览器应使用对应 H5 或其他支付方式 |
| SIGN_ERROR / VERIFY_SIGNATURE_FAIL | 商户证书私钥与 cert-serial-no 是否匹配，请求时间、签名串或代理改写是否异常 |
| 回调验签或解密失败 | 是否用对了微信支付公钥及 ID、APIv3 密钥，通知原文是否被代理改写 |
| 支付成功但订单未更新 | 通知 URL 是否公网可达、是否返回成功、是否验签解密、是否完成订单归属和金额校验 |
| 退款已受理但页面一直处理中 | 退款结果必须以退款通知或查询退款结果为准，不能以受理成功代替退款成功 |
| AppSecret 或私钥曾经泄露 | 立即在对应平台重置或作废，同步更新服务器并审计历史调用和资金记录 |
