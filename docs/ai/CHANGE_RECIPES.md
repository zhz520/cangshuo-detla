# 改动类型与固定动作

## 通用开工

1. 读 PROJECT_CONTEXT.md、FEATURE_MAP.md、PITFALLS.md。
2. 用 FEATURE_MAP.md 找后端、管理端、H5、数据库和测试。
3. 读目标 Controller/Service/页面和现有测试，不凭文件名猜逻辑。
4. 用 git status 确认分支、HEAD、未提交改动；不覆盖别人的源码。
5. 先写或补一个能复现问题的测试，再改实现。
6. 改完按 VERIFICATION.md 跑受影响检查，记录实际命令和结果。

## 改接口

- 后端 Controller 路径、方法、参数和响应字段先确认兼容。
- 管理端/H5 请求放 src/api 或 delta-mp/api，不在页面直接写 request。
- 更新 contracts/endpoint-baseline.json 和 OpenAPI baseline，再生成 types。
- 旧字段不删除；新增字段可空或有默认值。
- 跑 endpoint/OpenAPI/types 三个检查。

## 改数据库

- 只做新增表、可空列或安全默认值；不删除字段、不覆盖历史数据。
- 同时维护启动兼容逻辑和迁移文件；迁移要可重复执行。
- 金额、订单状态、退款、结算、授权字段必须有回归测试。
- 迁移前后都要备份；共享组升级由 worker 逐租户备份，不手工跳步骤。
- 手工 SQL 必须显式 utf8mb4，中文写入后回读校验。

## 改资金

- 先明确资金流向：余额、冻结金额、待结算收益、平台抽成、退款冲正。
- 覆盖金额、幂等、并发、状态机和失败回退。
- 提现相关先读 PITFALLS 的资金部分。
- 跑 AdminWithdraw 测试和财务 12 项检查。
- 任何“为了测试通过而清零客户资金”的做法都禁止。

## 改支付 / 退款

- 先确认公众号支付终端分流 P0 规则。
- 覆盖订单、充值、押金、短信套餐、实名套餐、授权中心功能。
- 覆盖微信内/微信外、手机/电脑、取消/成功/重复回调。
- 退款通知必须幂等；金额、商户号、AppID、交易号和本地支付单都要校验。
- 真实微信支付和模拟回调分开记录，不能用模拟代替真机。

## 改权限 / 演示账号

- 后端必须有权限校验，前端隐藏按钮不算。
- 演示账号写、上传、导出、WebSocket 和会变更状态的 GET 必须拒绝。
- 敏感字段脱敏；演示角色不能直接给 ADMIN。
- 覆盖正常管理员、客服、演示账号和匿名用户。
- 跑 GovernanceIntegrationTest、TokenRoleCaseTest 和后台路由审计。

## 改 UI / 主题

- 新页面使用 PageHeader/FormSection/AsyncState/DataTable。
- 请求统一走 src/api；消息统一用 toast/confirmAction。
- 只用 --el-* 主题 token，不写死颜色。
- 默认、暗黑、拟态三种主题都要看；320/390/430/768/PC 宽度都要检查。
- 跑设计系统静态测试和 browser-page-audit（可指定 AUDIT_THEME/AUDIT_ROUTE）。
- 表格列多时优先压缩列或使用“更多”菜单，不让固定列遮挡业务字段。

## 改租户

- 明确当前请求的 Host/TenantContext，所有查询、文件、Redis key、异步任务都带租户。
- 不跨租户复制数据；同 ID 不代表同一对象。
- 检查文件路径、缩略图、旧 URL、WebSocket 和定时任务。
- 用两个租户做隔离测试，不能用同一库的假数据代替。

## 改系统配置

- 配置项必须有唯一入口，避免公告/主题/会员/入驻多处重复。
- 非技术用户可见的配置用可视化表单/开关/下拉/单选/多选，不允许手写 JSON。
- 每个开关必须真实保存并被前端读取生效；保存后回读验证。
- 敏感密钥脱敏显示，保存后不回显原文。
- 演示账号对配置页面只读。

## 发布

- 先检查远端标签是否已存在，避免覆盖旧版本。
- 从干净工作区构建 backend/admin/h5，跑全部测试和静态引用检查。
- 生成发布 ZIP 和 manifest，校验大小/SHA-256/版本文件。
- 共享组走服务组签名计划、shared_worker validate/execute、逐租户备份和审计。
- 发布后验证容器、六域名、版本文件、API、静态 MIME、三库表数、财务和授权上报。
