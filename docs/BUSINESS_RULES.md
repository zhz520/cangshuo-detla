# 核心业务规则与功能矩阵

本文件记录长期不变、且最容易在开发中被漏掉的业务规则。具体接口、页面和测试路径由 `python scripts/ai_context.py` 从代码索引实时解析，不在本文件手抄完整清单。

## 1. 账号、登录与绑定

- 后台主登录方式由系统配置决定：`微信优先`或`手机号优先`。浏览器和 Host 决定展示方式，但最终以后端配置为准。
- 配置为微信优先但 AppID/公众号条件不满足时，前端降级到手机号登录并明确提示；不能静默失败。
- 手机验证码首次登录可以自动注册并直接下发正式 Token；不得强制设置密码，密码设置后置到个人中心安全模块。
- 微信授权未绑定手机号时只下发临时 Ticket，不下发正式 Token；Ticket 不能访问核心业务接口。
- 微信绑定手机号若命中已有账号，必须走短信校验和安全合并，不能报“请联系客服”让用户死锁。
- 允许解绑微信，不允许移除唯一手机号主身份；账号至少保留一种稳定登录方式。
- 已删除用户重新注册时必须释放手机号/OpenID 并创建新账号；历史订单和资金流水保留在原记录。
- 短信验证码接口必须前置图形验证码/滑块等防刷；验证码一次性、短有效期、次数限制，不能使用固定验证码。

相关测试方向：`UserAccountIntegrationTest`、`WechatIdentityServiceTest`、`WechatWebLoginServiceTest`、`wechat-binding.test.mjs`、`login-security.test.mjs`。

## 2. 商品、购买与订单

- 商品和分类图片按原比例展示；富文本描述前后台均需过滤 HTML/URL，图片限制最大宽度，不能把标签直接删除当纯文本。
- 商品购买状态由后端控制：正常购买、暂停购买但联系客服、完全暂停。联系客服模式只进入会话，不创建订单，也不绕过服务端禁止下单校验。
- 订单状态、订单归属、商品快照和价格以服务端为准；客户端不能通过修改参数改变订单金额或状态。
- 下单字段、商品规格和加价项必须由服务端校验；空数据、长文本、缺失字段和越权 ID 都要有失败路径。
- 游客下单的订单、支付、聊天和投诉只允许游客本人通过查单凭证访问，不能访问他人订单。
- 订单只能完成一次有效支付；已取消、已关闭或超时订单不能继续支付。
- 订单状态变更必须产生进度记录和必要通知；退款、售后和结算状态不能直接回写为已结算。

相关测试方向：`OrderPurchaseGateTest`、`OrderAssignmentCandidatesTest`、`PlayerBusinessRegressionTest`、`guest-checkout-ui.test.mjs`、`product` 相关测试。

## 3. 打手、指派与协同

- 订单指派候选必须按订单等级、所需人数、打手等级和接单状态筛选；不能把不可接单的低等级打手显示为可点击指派。
- 指派和接单接口仍要独立校验资格，前端按钮禁用不是安全边界。
- 单人订单允许邀请 1 名协同打手；多人订单必须满足人数和分成规则后才能开始服务。
- 协同邀请、接受、拒绝、换人必须有状态机，不能只用前端删除队员。
- 下单打手 A 邀请 B 后，B 无法继续时，A 有权将 B 替换为 C；替换必须校验 A 的订单归属、B 的当前队员状态、C 的资格和人数上限。
- 协同分成总和不能超过订单可分配金额；历史订单保留原分成快照。
- 打手入驻审核必须展示真实姓名、手机号、游戏 ID/段位、擅长服务、技能标签、证明截图和押金信息；通过/驳回必须留原因和操作日志。

相关测试方向：`PlayerBusinessRegressionTest`、`PlayerDirectoryIntegrationTest`、`StaffOrderTeamController` 和 `OrderTeamService` 相关测试。

## 4. 支付与退款

- 支付回调必须验签，并校验商户号、AppID、金额、币种、交易号、本地支付单和业务类型；重复通知必须幂等。
- 微信退款通知的空币种按 CNY 兼容处理；非空币种仍必须是 CNY，金额/退款单号/交易号不匹配时不得改变资金状态。
- 公众号支付在微信内置浏览器中直接拉起支付；在电脑或非微信浏览器中生成二维码并轮询订单状态。该规则是重要产品约束，除非用户明确要求，不得随意改回只支持一种方式。
- 电脑端扫码支付成功后，前端应自动关闭二维码并跳转订单详情；取消、超时、关闭页面要停止轮询。
- 支付方式必须独立按后台配置生效，不能因为未配置公众号支付就把历史支付恢复或自动确认。
- 金额、支付状态、退款状态以服务端数据库为准；客户端不能传入“已支付”“已退款”作为事实。
- 退款和余额扣减必须使用数据库事务与行锁；重复回调、并发审核和补偿任务必须幂等。

相关测试方向：`OrderRefundWorkflowTest`、`RepeatedRefundNotificationTest`、`platform-payment.test.mjs`、支付场景隔离和真实 MySQL 资金链路。

## 5. 钱包、押金、提现与结算

- 钱包和打手钱包不能出现负余额；交易余额必须满足 `balance_after = balance_before + 方向金额`。
- `WITHDRAW` 和 `WITHDRAW_COMPLETE` 只影响冻结金额或结算状态，不能按普通余额交易计算。
- 提现金额、收款姓名和实名姓名必须一致；收款人信息变更需重新校验，不能沿用旧快照。
- 提现申请冻结金额必须与待审核提现总额一致；审核、拒绝、失败和重试必须幂等。
- 押金支持全局金额和单人覆盖金额；单人配置优先，`0` 表示免押金，留空表示沿用统一规则。
- 押金支付、提现前补缴、押金退款都使用同一个有效应缴金额。
- 待结算收益必须与打手钱包 `pending_income` 一致；删除打手、注销账号、退款和结算不能把客户资金清零。
- 任何资金链路改动都要运行权威财务对账：12 项检查三库均为 0 违规，并使用真实 MySQL 验证。

相关测试方向：`AdminWithdrawConcurrencyTest`、`SettlementRecoveryTest`、`SettlementPendingFlowTest`、`financial_reconciliation.py`。

## 6. 客服、聊天与订单归属

- 客服只能访问被分配或有权限的订单、会话、投诉和提现；管理员权限不能由客服前端按钮代替。
- 游客聊天/投诉必须校验其与订单/打手的有效业务关系。
- 客服分配规则支持多个大分类和多个小分类，不能退化为只能选一个分类。
- 协同单换人、客服提醒、会话结束和评分都需要状态记录，不能只发一条通知。
- 聊天输入、消息发送、WebSocket 重连和离线补偿要保留用户内容和未读状态；不能因刷新丢失。

相关测试方向：`GuestChatAuthorizationTest`、`CsRoutingBatchRuleTest`、客服和订单团队相关集成测试。

## 7. 短信、实名和套餐

- 短信配置由授权中心统一持有阿里云 AccessKey，客户系统不再保存公司短信密钥；客户可以选择授权中心短信服务，也支持客户自行配置阿里云。
- 授权中心后台维护短信模板、签名、计费策略、套餐、接入凭据和使用量；只有在成功发送/成功回执后计入计费，失败不能计费。
- 短信服务区分配置与实际发送：没有完整配置或未启用时必须明确提示，不能显示“发送成功”或静默失败。
- 实名认证支持二要素；供应商可选阿里云、腾讯云或授权中心接入，配置必须能增删改查并显示启用状态。
- 实名失败要记录次数限制，后台可配置账号/手机号/IP 等维度的失败次数和冷却策略；不能无限重试刷供应商。
- 套餐支付规则与商品支付一致：配置公众号支付时微信内直接拉起，非微信环境生成二维码；支付回调成功后再发放额度。
- 功能商城只展示已购买且已启用的功能和权益；不能仅凭商品上架或授权目录中可见就展示入口。

相关测试方向：`SmsNoticeServiceTest`、`IdentityVerificationIntegrationTest`、`sms-account.test.mjs`、实名和支付回调测试。

## 8. 会员、优惠券、邀请、打赏与抢单

- 会员等级门槛、折扣率和权益由结构化配置驱动，已领取优惠券的金额/门槛不能被后台修改后追溯变价。
- 优惠券领取、核销、过期和退款恢复必须幂等；总量和每人限领由服务端校验。
- 邀请奖励和欠款追回是独立账本，不能直接修改用户可用余额；已追回只能关闭对应欠款记录。
- 打赏、抢单、等级验证和休息状态必须由服务端校验；休息中不能通过旧页面绕过抢单限制。
- 抢单验证码必须一次性、可刷新、过期失效；前端失败后不能强制留在空白验证码状态。

相关测试方向：`CouponAdminControllerTest`、`CouponControllerTest`、`MembershipAdminServiceTest`、`RewardGrabIntegrationTest`、`InviteRewardListenerTest`。

## 9. 权限、租户和审计

- 权限必须在后端校验；管理端路由 meta 只负责体验和菜单过滤。
- 资源归属必须校验：订单、聊天、投诉、支付、退款、提现、上传文件均不能仅凭 ID 访问。
- 管理员敏感操作写操作日志；客服不得执行超权退款、删除打手或修改资金。
- 所有租户请求显式解析租户；文件、Redis key、数据库连接和异步线程不能回退到默认租户。
- 跨租户文件请求返回 404/拒绝；同名相对路径不能串图。
- 密码、JWT、支付密钥、短信密钥、完整证件号和客户敏感数据不得进入日志或文档。

## 10. 主题、配置与功能目录

- 系统配置按基础、账号安全、支付、消息、业务配置等分组展示；配置要能保存并回读，不能只改提示文案。
- 开关关闭时应彻底隐藏或禁用对应功能；后端必须再次拒绝，不能只靠前端隐藏。
- 主题必须同时覆盖默认、暗黑和拟态；授权失效时回退默认主题，不能报域名错误或让页面空白。
- 配置字段必须可视化编辑，不允许让运营直接输入主题、会员、实名等 JSON。
- 授权中心的功能目录和客户本地启用是两个层面：前者决定可售/可授权，后者决定客户实际开启。
