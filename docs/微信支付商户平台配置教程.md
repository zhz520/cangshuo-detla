# 微信支付商户平台配置教程

适用对象：微信支付商户号超级管理员、技术负责人、安全联系人，以及负责客户公众号和服务器配置的运维人员。

最后核对日期：2026-11-02。

本文面向微信支付商户平台和微信公众平台官方后台，说明公众号支付（官方名称：JSAPI 支付）以及项目所需的公共凭据如何申请、绑定、配置和验收。客户程序里的字段怎么填，见[1.4.4 微信公众号支付配置教程](./1.4.4-微信公众号支付配置教程.md)。

## 一、三个域名/路径必须先分清

| 项目 | 在哪里配置 | 填什么 | 作用 |
| --- | --- | --- | --- |
| 网页授权域名 | 微信公众平台 → 设置与开发 → 公众号设置 → 功能设置 → 网页授权域名 | 不带协议的完整域名，例如 pay.example.com | 允许公众号网页授权回调到该域名并取得公众号 OpenID |
| 支付授权目录 | 微信支付商户平台 → 产品中心 → JSAPI 支付/开发配置 → 支付授权目录 | 带 https://、以“/”结尾的实际支付页面目录 | 校验在哪个页面可以调起微信支付收银台 |
| 通知地址 notify_url | 由客户后端下单时传入；项目在客户后台配置并写入请求 | 公网可访问的完整 HTTPS 路径，不带查询参数 | 微信支付把支付或退款结果通知给商户服务器 |

这不是三个可以互相替代的开关。只配置支付目录时，获取 OpenID 仍可能失败；只配置网页授权域名而没配置支付目录时，收银台仍可能报“当前页面的 URL 未注册”。微信官方也明确写明网页授权域名和支付授权目录分别配置，见[JSAPI 支付开发指引](https://pay.wechatpay.cn/doc/v3/merchant/4012791870)。

## 二、账号、产品和权限准备

### 2.1 公众号与 AppID

1. 登录微信公众平台。
2. 确认公众号类型和认证状态符合 JSAPI 支付要求。微信支付官方当前要求用于 JSAPI 下单和调起支付的 AppID 须为已认证的服务号，或已认证的政府或媒体类型公众号，并且已与商户号绑定。
3. 进入“设置与开发 → 开发接口管理 → 基本配置”。
4. 记录“开发者ID（AppID）”。把它与小程序 AppID、开放平台移动应用 AppID 分开保管。
5. AppSecret 只交给有权限的服务端技术人员，不写入网页、小程序包、移动 App 包或代码仓库。

参考：[开发接入准备（JSAPI 支付）](https://pay.wechatpay.cn/doc/v3/merchant/4015423216)、[开发必要参数说明](https://pay.wechatpay.cn/doc/v3/merchant/4013070756)。

### 2.2 商户号

1. 登录微信支付商户平台。
2. 进入“账户中心 → 商户信息”，记录完整商户号。
3. 确认该商户号主体、结算账户和业务经营范围与实际客户一致。
4. 同一项目联调时，AppID、商户号、商户 API 证书、APIv3 密钥和微信支付公钥必须属于同一套商户材料。

### 2.3 开通 JSAPI 支付

1. 在商户平台进入“产品中心 → JSAPI 支付”。
2. 查看产品权限状态；未开通时按页面提示提交申请。
3. 审核状态以商户平台实际页面为准，不要因为已保存客户后台配置就认为权限已开通。
4. 在“产品中心 → AppID 账号管理 → 关联 AppID”提交公众号 AppID。
5. 登录公众平台确认商户号绑定。
6. 在“产品中心 → AppID 账号管理 → 我关联的 AppID 账号”复核绑定状态。

微信官方说明 JSAPI 支付权限用于微信内置浏览器下单和调起收银台，并要求完成商户号与 AppID 绑定，见[开发接入准备](https://pay.wechatpay.cn/doc/v3/merchant/4015423216)。

### 2.4 其他支付方式的额外权限

授权中心的固定支付方式是 H5、JSAPI（小程序）、OFFICIAL（公众号）、NATIVE、APP。JSAPI 与小程序支付共享部分接口能力，但调起环境不同；H5、NATIVE、APP 各有独立的产品权限、AppID 类型和客户端接入要求。只勾选已经开通并完成客户端实现的支付方式。

## 三、配置公众平台网页授权域名

本节路径按当前公众平台常用菜单：**设置与开发 → 公众号设置 → 功能设置 → 网页授权域名**。

1. 登录微信公众平台。
2. 进入“设置与开发 → 公众号设置 → 功能设置”。
3. 在“网页授权域名”右侧点击“设置”。
4. 下载页面给出的校验文件，保留原文件名和内容。
5. 将校验文件原样上传到该域名根目录，确保可通过公网 HTTPS 访问。
6. 在域名输入框填写完整域名，不带 http://、https://、路径或端口，例如 pay.example.com。
7. 站点已启用 HTTPS 时，按平台要求完成 HTTPS 校验。
8. 保存并确认平台显示配置成功。

网页授权回调页必须使用 HTTPS。这个域名只授权网页授权，不能代替商户平台的支付授权目录。微信网页授权的 scope、code 换 OpenID 和回调约束，见[微信网页开发/网页授权](https://developers.weixin.qq.com/doc/service/guide/h5/auth.html)、[code 换 access_token 与 OpenID](https://developers.weixin.qq.com/doc/service/api/webdev/access/api_snsaccesstoken.html)。

## 四、配置 JSAPI 支付授权目录

本节入口：**微信支付商户平台 → 产品中心 → JSAPI 支付/开发配置 → 支付授权目录**。不同账号或灰度版本可能将“开发配置”显示在“产品中心”下，但关键词是“JSAPI 支付”和“支付授权目录”。

### 4.1 从实际支付页反推目录

假设微信内置浏览器最终加载并调起支付的页面是：

    https://pay.example.com/api/pay/wx/official/callback

则该页面所在的精确目录是：

    https://pay.example.com/api/pay/wx/official/

如果只配置站点根目录：

    https://pay.example.com/

则微信只校验协议和域名，同一域名下各路径都可匹配。这种方式方便，但授权范围更大；有条件时优先精确到实际支付模块。

### 4.2 配置步骤

1. 商户号超级管理员登录商户平台。
2. 进入“产品中心 → JSAPI 支付/开发配置 → 支付授权目录”。
3. 点击“添加”，填写实际目录。
4. 确认使用小写域名、HTTPS 协议、正确端口（非默认端口才写）、实际多级目录和末尾“/”。
5. 保存并等待页面提示生效，通常约 5 分钟。
6. 用微信内置浏览器实际打开支付页复测。

### 4.3 官方校验规则

- 一个商户号最多可配置 5 个支付授权目录。
- 不支持 IP 形式，不能写 https://192.168.1.1/。
- 必须使用已通过 ICP 备案的域名。
- 协议、域名、路径和大小写必须与实际支付页面一致。
- 精确到多级目录时会全匹配；根目录配置只校验协议和域名。
- 所有配置都必须以“/”结尾。

上述规则来自微信支付官方[配置 JSAPI 支付授权目录](https://pay.wechatpay.cn/doc/v3/merchant/4013287088)。

### 4.4 公众号支付的关键限制

JSAPI 支付只能在微信内置浏览器中发起。外部浏览器打开后再调起收银台，会出现类似“该商户暂不支持通过外部拉起微信完成支付”的错误。该限制及同一 AppID、同一 OpenID 的要求见[开发指引_JSAPI 支付](https://pay.wechatpay.cn/doc/v3/merchant/4012791870)。

## 五、准备 APIv3 凭据

项目需要四类不同凭据。它们不能混用，也不能互相替代。

| 凭据 | 商户平台入口 | 在项目中的用途 | 对应客户后台字段 |
| --- | --- | --- | --- |
| 商户 API 证书私钥 | 账户中心 → API 安全 → 商户 API 证书，使用证书工具申请并下载 | 对商户 APIv3 请求签名 | wx.pay.private-key-path |
| 商户 API 证书序列号 | 账户中心 → API 安全 → 商户 API 证书 → 管理证书 | 标识请求签名使用的商户证书 | wx.pay.cert-serial-no |
| APIv3 密钥 | 账户中心 → API 安全 → APIv3 密钥 | 解密支付/退款回调中的敏感信息 | wx.pay.api-v3-key |
| 微信支付公钥及公钥 ID | 账户中心 → API 安全 → 微信支付公钥 → 管理公钥 | 验证微信支付应答和回调；部分敏感字段加密 | wx.pay.public-key-path、wx.pay.public-key-id |

### 5.1 申请商户 API 证书

1. 商户号超级管理员登录商户平台。
2. 进入“账户中心 → API 安全 → 商户 API 证书”。
3. 下载并安装微信支付证书工具。
4. 在商户平台复制商户号和商户名称到证书工具。
5. 由证书工具生成请求串，回到商户平台粘贴。
6. 完成操作密码和短信验证。
7. 将商户平台返回的证书串粘贴回证书工具。
8. 在证书工具生成的目录中取得 apiclient_key.pem 和证书文件。
9. 在“管理证书”页面查看与私钥匹配的证书序列号。

商户 API 证书私钥只能在证书工具生成或导出，丢失后通常无法找回，只能作废后重新申请。官方步骤见[申请商户 API 证书](https://pay.wechatpay.cn/doc/v3/merchant/4012072428)。

注意：

- apiclient_key.pem 是私钥，只能放在服务器受控目录。
- 不要把 apiclient_key.pem、p12 文件或证书压缩包上传 GitHub、云盘、聊天群或工单附件。
- 证书序列号与私钥必须成对。更换其中一个却继续使用旧值会产生签名错误。
- 商户 API 证书与“微信支付公钥”不是同一个东西。

### 5.2 设置 APIv3 密钥

1. 进入“账户中心 → API 安全 → APIv3 密钥”。
2. 点击设置或修改。
3. 设置 32 个字符的密钥，使用数字和大小写字母的高强度随机组合。
4. 由授权人员安全保存。设置后通常不能在商户平台再次明文查看。
5. 将同一个值配置到客户后台 wx.pay.api-v3-key。

APIv3 密钥用于回调解密等场景，与 APIv2 密钥隔离。官方说明见[配置 APIv3 密钥](https://pay.wechatpay.cn/doc/v3/merchant/4012072195)和[开发必要参数说明](https://pay.wechatpay.cn/doc/v3/merchant/4013070756)。

如果遗失或怀疑泄露，应立即重置，并在所有使用该商户号的系统中同步更新。只改商户平台而不改应用，会导致回调解密失败。

### 5.3 申请微信支付公钥

1. 进入“账户中心 → API 安全 → 微信支付公钥”。
2. 点击申请或管理公钥。
3. 下载 pem 格式的微信支付公钥，通常文件名为 pub_key.pem。
4. 在公钥详情页记录公钥 ID。它通常以 PUB_KEY_ID_ 开头。
5. 将公钥文件和公钥 ID 一起配置到客户后台。
6. 查看商户平台是否显示公钥模式已启用或切换比例。

微信官方推荐新接入商户使用微信支付公钥模式；公钥用于验签和部分敏感字段加密，不等于商户 API 证书。官方说明见[产品介绍_微信支付公钥](https://pay.wechatpay.cn/doc/v3/merchant/4012153196)和[开发必要参数说明](https://pay.wechatpay.cn/doc/v3/merchant/4013070756)。

重要：先确认应用已完成公钥验签、回调兼容和敏感字段处理，再在商户平台开启或完成公钥模式切换。提前切换可能让仍在用平台证书的旧代码无法验签或解密。

## 六、配置支付和退款通知

### 6.1 支付通知

客户项目通过下单接口把后端配置的地址传入 notify_url。本项目推荐：

    https://客户公网域名/api/pay/wx/notify

微信支付官方要求：

- 必须是完整 URL，以 https:// 开头。
- 域名和 IP 必须能被微信支付服务器从公网访问。
- 不能填 localhost、127.0.0.1、192.168.x.x 等内网地址。
- 不能携带查询参数。
- 商户系统收到通知后应在 5 秒内返回成功应答。
- 通知可能重复发送，必须按通知 ID、支付单号或交易号做幂等处理。
- 不能只依赖通知，通知延迟或遗漏时必须主动查单。

见[回调通知注意事项](https://pay.wechatpay.cn/doc/v3/merchant/4012075420)。如果该回调页同时用于网页授权返回，则它的域名还必须配置进公众平台的网页授权域名；服务器到服务器的 notify_url 本身不会被公众平台的网页授权域名设置自动放行。

### 6.2 退款通知

项目推荐使用：

    https://客户公网域名/api/pay/wx/refund-notify

退款申请受理不等于退款成功。最终状态必须来自退款结果通知或查询退款接口。回调内容需要用 APIv3 密钥解密并验签。见[订单退款开发指引](https://pay.wechatpay.cn/doc/v3/merchant/4013071031)和[退款结果通知](https://pay.wechatpay.cn/doc/v3/merchant/4012268885)。

### 6.3 反向代理要求

- 保留 HTTP POST 方法、原始请求体及 Wechatpay-* 签名相关请求头。
- 不缓存回调响应。
- 不增加浏览器登录态或 CSRF 校验。
- 不能把公网 HTTPS 请求重写成内网 HTTP 后再让签名校验依赖原始 Host 的场景。
- 让通知接口快速返回成功，耗时业务放到事务后的任务中处理。
- 对请求做验签、消息解密、商户号、AppID、币种和金额核对，不能只凭 request body 中的“成功”状态。

## 七、将官方平台材料填到项目

| 官方后台材料 | 客户后台固定键 | 授权中心字段 | 说明 |
| --- | --- | --- | --- |
| 商户号 | wx.pay.mch-id | 无直接对应字段 | 由项目实例使用，授权中心只声明通道 |
| 小程序或现有通用支付 AppID | wx.pay.appid | appId | 不要把公众号 AppID 覆盖到这个字段 |
| 公众号 AppID | wx.pay.official-appid | officialAppId | 必须与商户号绑定 |
| 公众号 AppSecret | wx.pay.official-appsecret | officialAppSecret | 服务端敏感凭据 |
| 公众号回跳 HTTPS Origin | wx.pay.official-return-origin | officialReturnOrigin | 只填协议、域名和可选端口，不含路径 |
| 支付通知 URL | wx.pay.notify-url | 无直接对应字段 | 由客户后端使用 |
| 退款通知 URL | wx.pay.refund-notify-url | 无直接对应字段 | 由客户后端使用 |
| APIv3 密钥 | wx.pay.api-v3-key | 无直接对应字段 | 不应下发到浏览器或客户端 |
| 商户证书序列号 | wx.pay.cert-serial-no | 无直接对应字段 | 与私钥成对 |
| 商户私钥文件 | wx.pay.private-key-path | 无直接对应字段 | 后台上传，保留受控服务器路径 |
| 微信支付公钥 ID | wx.pay.public-key-id | 无直接对应字段 | 以 PUB_KEY_ID_ 开头 |
| 微信支付公钥文件 | wx.pay.public-key-path | 无直接对应字段 | 后台上传，不能与商户私钥混淆 |

授权中心的微信支付方式只能从 H5、JSAPI（小程序）、OFFICIAL（公众号）、NATIVE、APP 中选择。授权中心字段固定为 appId、officialAppId、officialAppSecret、officialReturnOrigin。实际证书和 APIv3 密钥仍应保存在客户后端，并通过项目实例的受控配置获取。

## 八、推荐上线顺序

1. **资料核验**：确认公众号主体、认证状态、商户主体、结算账户和经营场景。
2. **产品权限**：先开通并等待 JSAPI 支付权限，再完成 AppID 绑定。
3. **域名准备**：做 HTTPS、DNS、备案和服务器安全组检查。
4. **公众平台**：配置网页授权域名并上传校验文件。
5. **商户平台**：配置支付授权目录。
6. **凭据准备**：申请商户 API 证书、设置 APIv3 密钥、申请微信支付公钥。
7. **测试环境**：客户后台先关闭总开关，填写全部参数并上传文件；在可控环境验证生成授权链接、换 OpenID 和预支付下单。
8. **正式小额交易**：使用真实且极低金额的商品在微信内置浏览器完成支付，核对真实扣款、通知、查单和退款。
9. **能力放开**：仅将已经验收的 OFFICIAL（公众号）或其他支付方式设置为客户项目可用。
10. **监控与留痕**：持续检查授权失败、下单失败、验签失败、通知异常、退款异常和证书到期。

## 九、逐步测试清单

### 9.1 静态配置检查

- 公众号 AppID 与商户号绑定状态为已生效。
- JSAPI 支付产品权限已开通。
- 网页授权域名能通过平台校验，回调页能在微信内打开。
- 支付授权目录与实际发起支付页的目录完全一致。
- official-return-origin 是不含路径的 HTTPS Origin。
- notify-url 和 refund-notify-url 都是公网完整 HTTPS URL，无查询参数。
- 商户私钥与证书序列号匹配。
- 微信支付公钥与公钥 ID 匹配。
- APIv3 密钥为 32 字符，并已在服务器保存。
- 项目全局微信支付开关仍未在未熟悉配置的情况下提前开启。

### 9.2 公众号授权检查

1. 在微信内打开测试支付页。
2. 观察是否跳转到 open.weixin.qq.com 的网页授权地址。
3. 授权回调 URL 的域名是否等于公众平台网页授权域名。
4. 后端是否用同一公众号 AppID 换取到 OpenID。
5. 不记录完整 code、AppSecret 或 OpenID 到普通日志。

### 9.3 收银台检查

1. 后端创建 JSAPI 预支付单。
2. 页面必须在微信内置浏览器内调起。
3. 下单 AppID 与当前公众号 AppID 一致。
4. 订阅消息或本地订单不要代替微信支付结果。
5. 如果提示“当前页面的 URL 未注册”，回到支付授权目录逐字比对。
6. 如果提示 AppID 与 OpenID 不匹配，检查是否混用了小程序和公众号身份。

### 9.4 支付结果检查

1. 低金额真实支付后，确认商户平台能查到交易。
2. 确认支付通知请求到达 notify-url。
3. 服务端验签、解密并核对 AppID、商户号、币种、金额和订单号。
4. 重复投递两次相同通知，确认只入账一次。
5. 断网或通知延迟时，主动查单仍能得到正确状态。

### 9.5 退款检查

1. 通过项目管理员发起一笔低金额退款。
2. 确认退款申请被受理。
3. 以退款通知或查询退款结果确认最终成功，不以受理状态代替。
4. 检查退款成功后订单、余额或原支付记录的状态。
5. 对重复退款通知验证幂等。

## 十、安全与轮换

- 公众号 AppSecret、APIv3 密钥、商户私钥只能在服务端受控环境使用。
- 不在前端 bundle、源码注释、安装包、截图、聊天记录或工单中保存密钥。
- 后台只显示密钥是否已设置，不默认回显明文。
- 文件权限设置为仅应用运行账号可读；备份也需保留同等访问控制。
- 日志中对敏感字段做屏蔽，尤其是 AppSecret、code、私钥、APIv3 密钥和签名原始串。
- 商户 API 证书有效期通常为 5 年。到期前先申请新证书，部署新私钥和序列号，观察旧证书调用量降为 0 后再作废旧证书。
- 微信支付公钥和商户 API 证书不是可互换的两个模式。公钥切换时先完成代码兼容，再按商户平台的灰度状态切换。
- APIv3 密钥轮换需要同步更新所有支付服务和任务，不能只更新其中一个实例。
- 对证书、密钥、域名和支付方式的修改记录操作人、时间、项目和原因。

## 十一、常见问题定位

| 问题 | 第一检查点 | 第二检查点 |
| --- | --- | --- |
| 网页授权 10003 | 公众平台网页授权域名 | 回调 URL 的协议、域名、端口是否严格一致 |
| 网页授权 10005 | 公众号类型与认证状态 | 当前 scope 是否该公众号具有权限 |
| 当前页面 URL 未注册 | 商户平台支付授权目录 | 微信内实际 URL 的目录、大小写和末尾斜杠 |
| 外部浏览器无法拉起 JSAPI | JSAPI 只能在微信内置浏览器发起 | 外部浏览器改走 H5，小程序走小程序支付 |
| AppID 与 OpenID 不匹配 | 下单用的 AppID 与授权用的 AppID | 是否把公众号 OpenID 与小程序 OpenID 对调 |
| SIGN_ERROR | 商户私钥与证书序列号 | 请求体、签名串、系统时间和代理是否改写 |
| 公钥验签失败 | Wechatpay-Serial 是否为 PUB_KEY_ID_* | 是否使用对应公钥、是否启用公钥模式 |
| 回调无法解密 | APIv3 密钥是否 32 字符且全实例一致 | 回调原文是否被代理或框架改动 |
| 收不到支付通知 | notify_url 是否 HTTPS、公网、无参数 | 是否能在 5 秒内成功响应，防火墙是否拦截 |
| 退款状态一直处理中 | 退款通知是否到达 | 查询退款结果；退款有到账延迟 |
| 已保存配置但仍不可用 | 微信侧权限和绑定是否生效 | 客户端是否真正实现对应支付方式 |
