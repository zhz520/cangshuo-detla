- 生产备份、clone 恢复、迁移到 65 表已完成；clone 财务 12 项 0 违规。
- JAX clone 已作为第二个租户加入暂存共享服务组，与 742 同时运行。
- 双域名路由、两个数据源、两个 Redis 命名空间、JAX/742 租户文件和缩略图均通过；未登记 Host 404。
- 授权中心已收到 JAX `version=1.12.0` 上报；1.12.0 已登记为正式 Release，当前可选更新项为空。
- 2026-11-11 已用现有 JAX 数据库和上传启动 `delta-shared-backend` 单租户试点，Nginx 改用共享后端别名；该步骤没有迁移数据库，后续完整共享服务组迁移仍按本文执行。

## 2. 生产共享迁移前置条件

- [ ] 生产共享服务组已部署：共享后端、共享 MySQL、独立 Redis、后台/H5 静态容器、租户注册、监控和连接预算。
- [ ] 创建 JAX 目标库和独立数据库账号，导入 `delta_game` 并核对 65 张表及关键行数。
- [ ] JAX 文件同步到 `upload/jax/`，文件差异报告 identical；财务报告 passed。
- [ ] 1.12.0 已登记为正式 Release/授权中心版本，或明确批准 JAX 专用发布计划。
- [ ] JAX 客户确认维护窗口、验收人和回滚负责人。
- [ ] Nginx/证书、CORS、WebSocket、公众号配置（如启用）逐项核对；支付保持关闭。
- [ ] 准备旧独立服务保留时间和回滚步骤。

## 3. 切换步骤

1. 变更单审批，记录版本、commit、release manifest、维护窗口和负责人。
2. 停写前做最终 MySQL、上传、私密、平台配置和 `.env` 备份，校验 SHA-256。
3. 停止 JAX 写入，排空任务和聊天，确认支付保持关闭。
4. 导入目标库，核对表数、关键行数、钱包/订单/交易/退款/提现/结算。
5. 文件同步：`file_delta.py compare/sync/verify`，确认 missing/changed 为 0。
6. 财务对账：`financial_reconciliation.py audit --fail-on-violation`。
7. 把 JAX 租户注册到生产共享注册文件，验证两个数据源和 `delta:jax:` 缓存键。
8. 切换 `jaxapi.kkimg.top` / `jax.kkimg.top` 到共享后端，验证站点、后台/H5、API、文件和 WebSocket。
9. 客户完成登录、下单、派单、聊天、退款、提现、上传和 H5 返回键验收。
10. 观察期结束后停止旧 JAX 独立容器，保留备份；不能删除旧数据库。

## 4. 回滚

- 先把域名/Nginx upstream 切回旧 JAX 独立后端，验证旧站点和 API。
- 恢复旧 JAR、旧后台/H5 和旧 Compose 覆盖；健康检查失败时保留维护门禁。
- 目标库写入无法安全合并时，停止共享后端写入并恢复最终备份；恢复后逐笔核对 JAX 订单、退款和账户余额。
- 支付保持关闭，避免回滚期间产生支付差异。
- 状态机记录 `rolled_back`，保留旧库、上传、配置和备份。

## 5. 验收清单

- [ ] 双域名解析到正确入口，未登记 Host 拒绝。
- [ ] 后台登录、订单、客服、财务、系统设置正常。
- [ ] H5 工作台、订单、待办、消息、个人中心和返回键正常。
- [ ] 历史图片、缩略图、新上传文件可访问，目录为 `upload/jax/`。
- [ ] 微信支付保持关闭，页面不提供不可用的支付入口。
- [ ] 客户确认数据、订单、退款、提现和文件无差异。
- [ ] 其他租户（742/747 等）未受影响。

## 6. 当前结论

JAX 的独立版升级和共享租户暂存验证已完成；生产共享切换还缺共享服务组、正式 Release 登记、维护窗口和客户验收，当前不能直接切换。
