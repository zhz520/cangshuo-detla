# Delta 多租户实施进度

- 更新日期：2026-11-10（Asia/Shanghai）
- 实施分支：`codex/multitenant-foundation`
- 基线：`main` 的 1.11.2 与 `codex/multitenant-execution-plan` 执行文档
- 当前结论：基础隔离闭环已实现并通过后端全量测试；共享模式仍不得用于生产。

## 1. 本次已落地

### 1.1 域名与租户上下文

- 新增 `TenantProperties`、`TenantRegistry`、`TenantHosts` 和 `TenantIds`，域名在启动时规范化并检查重复归属。
- 新增 `TenantRequestFilter`，只使用 Servlet 容器解析后的 `getServerName()` 查询登记域名；未登记域名返回 404，停用租户返回 503。
- 请求处理期间通过 `TenantContext` 传播租户，`finally` 清理线程上下文；同一线程内显式拒绝切换租户。
- `tenant.enabled` 默认为 `false`，现有客户继续沿用原单租户路径。

### 1.2 登录与会话

- 共享模式下 JWT 和 Redis 登录上下文新增 `tenantId`。
- 旧 Token 没有租户声明时，在共享模式下拒绝认证，要求重新登录。
- 同一用户 ID 在两个租户创建的 Token 不能跨租户通过认证。
- 游客、用户、打手、客服和管理员仍沿用原有角色校验。

### 1.3 数据源

- 新增 `TenantRoutingDataSource`，每次 JDBC 连接从当前可信租户上下文选择目标库。
- 没有租户上下文、租户未登记或目标库缺失时直接失败，不落回默认客户库。
- 新增 `TenantDataSourceConfiguration`，仅为启用租户创建连接池；默认单租户不加载。
- 每租户可配置连接池上限、最小空闲数和连接等待时间，默认最大 8 个连接。
- `DatabaseCompatibility`、`GovernanceSchema` 和 `AnalyticsSchema` 在共享模式下逐启用租户执行；单租户仍执行一次。
- 共享模式禁止使用全局首次管理员初始化，避免把同一管理员写入所有客户。

### 1.4 Redis 与后台任务

- 共享模式下键格式为 `delta:<tenant_id>:<业务键>`。
- `RedisService`、登录态、系统配置、验证码、限流、密码设置凭据、公众号绑定、公众号支付状态和订单支付超时键均已接入命名空间。
- `@Scheduled` 任务通过 `TenantScheduler` 逐启用租户执行，单租户失败只记录该租户，不阻塞其他租户；异步任务通过 `TenantTaskDecorator` 传递并恢复租户上下文，包括 `CallerRunsPolicy` 场景。

### 1.5 支付、公众号和小程序

- 微信支付客户端按租户缓存，共享模式不再用全局商户凭据兜底；证书路径、通知地址和配置更新均按租户数据库/缓存读取。
- 公众号 access token 按租户缓存，租户 A 的 token 不会发送租户 B 的消息。
- 小程序登录和订阅消息通过 `TenantWxMaServiceProvider` 按租户创建客户端；没有租户小程序配置时明确停止微信登录/订阅发送。
- 支付和退款回调先由可信 Host 定位租户，再使用该租户的支付配置验签；账务写入沿用现有幂等和行锁逻辑。

### 1.6 聊天、文件和 WebSocket

- WebSocket 握手绑定租户，Origin 必须属于同一租户；每条消息都恢复租户上下文，连接键包含租户。
- 文件公共路径为 `upload/<tenant>/yyyy/MM/dd/`，历史单租户 URL 保持兼容；共享模式下旧的无租户目录不能作为公共资源直出。
- CORS 按请求 Host 和 Origin 校验同一租户；WebSocket 允许来源由共享注册域名生成，并在握手层再次校验。
- 维护开关按租户独立，租户 A 进入维护不会关闭租户 B。

### 1.7 授权状态

- 授权许可证、授权状态、项目快照、更新选择和执行器文件写入 `platform/tenants/<tenant>/`，每个租户保留原实例 UUID 和客户编号。
- `PlatformReporter` 逐租户同步，`PlatformRemote` 的缓存、去重和更新计划状态按租户分开。
- 授权中心提供只读 `/api/runtime/tenants` 导出，运维仍需在受保护注册文件中合并数据库凭据；共享租户后台不能独立安装后端更新。

## 2. 实际验证

使用 Temurin JDK 17.0.21 和 Maven 3.9.9 执行：

```powershell
cd D:\codeStudy\code\cangshuo-detla\delta-game
mvn -pl delta-admin -am test
```

结果：后端全量 **304 项测试通过，0 failures / 0 errors**。租户、支付、授权和原有业务回归共覆盖：

- 两个租户具有相同表名、相同查询时分别读取自己的 H2 数据库。
- 空上下文和未知租户均拒绝，不落回默认库。
- 未登记域名和伪造 `X-Forwarded-Host` 无法进入业务链。
- 不同租户的同一用户 ID Token 不能互相认证。
- 相同 Redis 业务键在两个租户得到不同物理键。
- 租户切换冲突、上下文清理和停用租户拒绝。

测试通过不代表真实 MySQL 迁移、真实商户回调、真实 WebSocket 设备和生产切换已完成。

授权中心功能分支 `codex/tenant-registry-export` 另完成 58 项 Node 测试，Vite 生产构建通过；只读注册导出尚未合并到授权中心 `main`，也没有部署到生产。

## 3. 当前仍不能启用共享模式的原因

运行时隔离已完成大部分改造，以下能力仍是共享模式上线的门禁：

| 能力 | 当前风险 | 后续工作包 |
| --- | --- | --- |
| 微信支付客户端缓存 | 已按租户隔离；仍需用真实商户配置做回调验收 | W5 |
| 支付/退款回调识别 | 已由可信 Host 绑定租户，仍需维护窗口接收与对账演练 | W5/P3 |
| WebSocket 连接和消息 | 已绑定租户和 Origin；仍需真实微信/QQ/iOS/Android 设备验收 | W6 |
| 文件上传与私密文件 | 已按 `upload/<tenant>/` 隔离；仍需迁移旧文件并验收历史 URL | W6/P3 |
| CORS / WebSocket Origin | 已按租户校验；仍需 Nginx 真实域名与回调配置核验 | W6/W8 |
| 定时任务 | 已逐租户运行并有失败隔离；仍需高峰与重复执行演练 | W6 |
| 授权与平台状态 | 已按租户保存独立许可证和状态；仍需授权中心实例映射验收 | W7 |
| 租户开通接口 | 已有租户注册文件读取；授权中心功能分支新增只读注册导出，仍需合并发布、凭据合并和操作审计 | W1 |
| 发布与迁移执行器 | 还未支持共享服务组和逐租户迁移状态 | W9 |
| 生产容量数据 | 尚未采集，不能承诺客户数或内存节省比例 | P0 |

因此，生产环境必须保持：

```yaml
tenant:
  enabled: false
```

不得为了验证方便直接在生产打开该开关。共享模式测试需要独立、合成的数据库和域名，不能连接真实客户库。
