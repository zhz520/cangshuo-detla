## 已修复

- 客服临时冻结原先只发送固定值，实际会变永久冻结；现在按所选解冻时间写入，并新增客服解冻接口和按钮调用，不再误用管理员接口。
- 禁止删除当前登录管理员或最后一个启用中的管理员。
- 退款申请处于 REQUESTED、初审、终审、PROCESSING 或 FAILED 时，自动确认、订单结算和待结算收益释放均暂停。
- 暂未开放的部分退款由接口拒绝，后台仲裁选项禁用，避免部分退款被记成整单退款。
- 关闭“新支付”不再停止历史 PAYING/REFUNDING 的支付对账和退款恢复。
- 共享租户 Redis 支付超时键带租户前缀，超时监听改为从任意前缀解析订单号。
- CS 工作台财务字段在缺少 finance.read 时返回空值，不再向任意客服暴露成交额和待提现数。
- H5 工作台“待审核”快捷项改为打开待办中心；客服不再看到仅管理员可用的提现入口。
- 结算台账使用本地日期，清空日期范围后清空旧数据。
- 后台订单指派/结单、投诉退款/冻结按钮按权限显示；部分退款选项禁用。
- 下单下拉字段必须有选项；打手昵称不能为空；聊天发送失败保留输入；订单详情与进度拆开加载；接力通过和未知投递重发增加确认；图片型内容页面可保存。

## 仍需单独处理的风险

- 高：GET /file/** 仍对匿名公开，聊天、订单进度和投诉附件没有私有访问控制；需要签名 URL 或鉴权文件代理，不能简单改为全量登录，否则会破坏公开商品图和品牌图。
- 高：生产日志仍有微信退款通知与本地退款单不一致错误。当前支付单均已 REFUNDED，没有卡在 REFUNDING 的记录，财务 12 项 0 违规；需要从商户平台核对是否存在旧退款单重复通知或二次退款，确认前不自动忽略。
- 高：自动退款进入 REFUND_FAILED 后没有自动重试或退款申请待办；需增加失败队列和人工处理入口。
- 中：自动取消/自动确认任务先查 ID 再按时间批量更新，跨越截止时间的订单可能出现状态与进度/优惠券释放不一致；建议改为按查询到的 ID 更新。
- 中：支付/退款恢复每次固定取最旧 20 条，持续失败的坏记录会阻塞后续记录；需要重试时间和游标。
- 中：公开支付回调没有频控，伪造报文会造成签名校验和日志压力；需要按 IP/来源限流并压缩异常日志。
- 中：管理端 H5 长聊天会话的高度约束、部分弹窗的局部错误状态和少数聊天/投诉操作权限提示仍需继续按页面验收。
- 低：租户注册文件启动校验只拒绝 others 权限，实际生产文件为 0600；可将校验收紧为仅 owner 可读写。
