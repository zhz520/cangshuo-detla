# 1.9.0 通知中心、退款审批与运营看板

## 通知中心

- 公众号模板通知与业务短信共用同一套业务事件，但分别记录发送任务、失败原因和重试状态。
- 客户、打手、管理员、客服分别使用独立模板组，不再共用一份角色模板。
- 支持新订单、订单状态、退款状态、投诉状态和人员/素材审核五组事件。
- 已支付且未指定打手的订单向全部在线打手广播；没有在线打手时向全部正常打手广播，并注明“当前暂无打手在线”。
- 已指定打手的订单只通知指定打手；尚未接受的组队邀请人不会收到客户姓名和订单金额。
- 当班客服按 `staff_shift` 状态接收订单、投诉、退款和人员审核通知；下班客服不接收，ADMIN 始终接收。
- 退款通知只发给明确拥有 `order.refund` 权限的客服，通配权限不包含退款权限。
- 通知任务使用业务去重键；公众号和短信队列限制并发重复入队，投递结果未知时停止自动重发，由管理员确认后再重试。
- 终态通知记录保留 30 天，待发消息超过 1 天自动过期；清理任务独立于通道开关运行。

## 退款与售后

- 新增客户和客服发起、客服初审、ADMIN 终审、支付渠道处理、成功、失败和重试的退款流程。
- 客服只能核验并提交初审意见，不能执行资金退款；管理员终审通过后才调用原支付渠道。
- 客户只能读取退款状态、金额、本人填写原因和面向客户的处理说明，后台审核人、内部备注、来源编号和渠道内部字段不会返回客户端。
- 游客影子账户可以给自己的订单申请和查看退款。
- 投诉仲裁产生的退款进入同一审核流程；ADMIN 驳回投诉退款时同步关闭投诉并恢复订单结算，避免订单停留在 `ARBITRATED`。
- 同一订单只允许一个活动退款；退款请求支持客户端幂等号，支付与退款记录使用行锁。

## 数据看板

- 新增今日访客、登录日活、新增用户、订单、有效订单、成交额、退款和完成订单指标。
- 支持今日与昨日对比、近 7 天/30 天趋势和访问到完成的订单漏斗。
- 在线、离线、冻结打手和当班客服数量可查看；点击打手人数可下钻查看 ID、昵称、头像、等级、进行中订单和最后在线时间。
- 访客数据使用 HMAC 摘要，不保存原始 IP、UA 或公开访客标识。
- 移动客服工作台增加登录日活指标、待办角标、权限过滤、动态排班状态和失败重试。

## 审核与手机后台

- PC 端将接力审核与换人审核合并为“履约审核”，底层订单状态和资金规则保持独立。
- 手机端新增退款初审、履约审核、在线/离线下钻和卡片式客服/管理员工作台。
- 手机待办支持按审核类型筛选，退款、接力、换人和入驻待办会携带对应业务编号进入处理页面。
- 退款、履约列表支持分页加载、错误提示和重试，不再只读取首批记录。
- 管理员与客服在订单列表和详情中直接查看完整客户手机号；用户端和打手端不返回其他人的手机号。

## 升级说明

- 后端、管理后台和 H5 必须同批更新，目标版本均为 `1.9.0`。
- 本次包含数据库兼容升级：新增实名、隐私、退款、通知队列和访问分析结构，并补齐公众号通知去重键与投递索引。
- GitHub 正式版发布后由发布方通知客户。客户自行进入「功能与更新 → 系统更新」，选择所需更新内容并启动安装；维护人员不代替客户点击客户端更新。
- 更新失败时使用系统更新备份回退，并依据组件版本及健康检查结果排查。

## 配置说明

公众号模板组配置键：

- `wechat.official.templates.user`
- `wechat.official.templates.player`
- `wechat.official.templates.admin`
- `wechat.official.templates.cs`

短信模板组配置键：

- `sms.notification.templates.user`
- `sms.notification.templates.player`
- `sms.notification.templates.admin`
- `sms.notification.templates.cs`

每个模板组可使用事件组：`new_order`、`order_status`、`refund_status`、`complaint_status`、`staff_review`。模板字段数据源支持 `message`、`status`、`time`、`orderNo`、`amount`、`customerName`、`playerName`。
