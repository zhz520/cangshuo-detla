# 微信支付 IPv4 出口修复记录

- 日期：2026-11-13
- 影响客户：742（`chuan742.idcgov.cn`）
- 当前客户端版本：1.14.8（运行时配置修复，不改变组件版本）
- 数据库：无变更

## 1. 现象

742 客户在微信公众号内发起订单支付时，微信授权后无法正常进入支付；后台留下多笔 `WECHAT_OFFICIAL` 状态的 `PAYING` 支付记录。后端同时出现：

- `WxPaymentRecoveryTask` 查询微信支付订单时报 `HttpException: Send Http Request failed`。
- 根因包含 `java.net.SocketException: Network is unreachable` 和 `SocketTimeoutException`。
- 公众号支付回调日志中还有一条重复回调触发 `公众号支付授权已过期`，这是同一授权 state 被首次回调消费后的重复请求，不是本次主因。
- 预支付恢复后，微信内置浏览器页面仍停在“正在调起微信支付”。响应头同时存在后端 CSP 和静态 Nginx 的旧 CSP，旧 Nginx 的 `script-src 'self'` 阻止了支付页内联调起脚本执行。

## 2. 根因

共享后端容器没有 IPv6 出口，但 `api.mch.weixin.qq.com` 的 DNS 返回 IPv6 地址。Java/OkHttp 微信支付 SDK 优先尝试 IPv6 时得到 `Network is unreachable`，导致 JSAPI 预支付创建和支付对账查询失败。

只读验证：

- `curl -6 https://api.mch.weixin.qq.com/` 失败。
- `curl -4 https://api.mch.weixin.qq.com/` 返回 HTTP 响应。
- JVM 原未设置 `java.net.preferIPv4Stack`。

## 3. 修复

- Dockerfile 的 Java 启动参数增加 `-Djava.net.preferIPv4Stack=true`。
- 单实例 Compose 和共享 Compose 的 backend 服务增加 `JAVA_TOOL_OPTIONS=-Djava.net.preferIPv4Stack=true`。
- 生产 `/www/delta/shared/compose.production.yml` 已做同名配置，原文件备份为 `compose.production.yml.bak-ipv4-20261113-1235`。
- 仅重建 `delta-shared-backend`，使用当前 1.14.8 JAR，不重建数据库、静态容器或客户端制品。
- 生产 `/www/delta/nginx.conf` 原缺少支付回调专用 location，已补上并通过 `nginx -t` 后 reload `delta-h5` 和 `delta-admin-ui`；原文件备份为 `nginx.conf.bak-pay-csp-20261113-1247`。仓库模板 `deploy/baota/nginx.conf` 已包含该 location。

## 4. 验证

- 共享后端 `running + healthy`。
- `JAVA_TOOL_OPTIONS=-Djava.net.preferIPv4Stack=true` 已生效，Java 属性 `java.net.preferIPv4Stack = true`。
- 重启后近期未再出现微信支付 SDK 的 `Network is unreachable` 错误。
- 支付回调响应现在使用 `script-src 'unsafe-inline'`，旧 `script-src 'self'` 不再覆盖支付页；回调页已通过 `nginx -t` 和 reload 验证。
- MySQL、Redis、管理后台、H5 容器保持 healthy。

## 5. 仍需客户验证

本次修复解决的是支付 SDK 的 IPv6 出口失败和支付页 CSP 拦截。已有 `PAYING` 记录不会被伪造为已支付；客户需要关闭当前停住的页面，回到订单重新点击支付或重新扫码，微信支付才会重新完成 JSAPI 预支付和支付确认。若仍失败，应按回调时间继续检查公众号网页授权域名、AppID/AppSecret 和微信支付商户平台配置。

## 6. 回滚

移除 backend 的 `JAVA_TOOL_OPTIONS`，恢复 `compose.production.yml.bak-ipv4-20261113-1235`，再重建共享后端即可。回滚不会影响数据库和静态发布目录。
