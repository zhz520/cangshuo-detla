# 配置与外部服务

本文件只记录会改变业务行为或上线条件的配置。具体字段的源码位置由脚本索引解析；禁止把密钥、证书、完整手机号写进文档。

## 1. 系统配置分组

公开站点配置 `/system/config/site` 额外返回只读的 `backend_version` 与 `backend_build_id`，用于判断各租户运行的是否为同一后端构建；它们不是业务配置，后台不可编辑，也不能用版本号相同替代制品摘要比对。

运营后台系统配置按以下业务分组；开关必须能保存、回读并真正影响前后台。

| 分组 | 主要内容 |
| --- | --- |
| 基础设置 | 平台名称、副标题、Logo、后台标题、技术支持、站点入口 |
| 账号与安全 | 主登录方式、密码登录开关、手机号登录、微信登录、实名认证、内容风控、年龄确认 |
| 支付与交易 | 支付开关、公众号/小程序/Native/H5 支付、微信商户材料、退款和下单策略 |
| 消息与通知 | 短信、邮件、公众号模板、客服通知、接收人和模板预览 |
| 业务配置 | 打手入驻、提现结算、营销、会员等级、邀请、功能商城 |

要求：

- 不把所有配置塞进一个超长页面；不滥用折叠面板；关键配置必须有明确的未配置状态。
- 主题、会员、实名、短信模板等不能要求运营直接输入 JSON；使用勾选、单选、下拉和结构化表单。
- 配置保存后重新读取必须一致；演示账号只读，不显示保存按钮。
- 任何“未配置”状态都要给出可定位的配置入口和必要材料说明。

## 2. 登录与微信

- 主登录方式：`微信优先` 或 `手机号优先`。
- 允许账号密码登录是独立开关；关闭时前端不显示密码入口，后端密码登录接口也必须拒绝。
- 微信优先但 AppID/公众号不满足时，降级到手机号登录并 Toast 提示。
- 微信 OAuth 需要公众号 AppID、AppSecret、授权回调和域名匹配；公众号网页授权和微信支付 AppID 不混用。
- 微信未绑定手机号时只能得到临时 Ticket；换正式 Token 前必须完成短信绑定。
- 绑定已有手机号时走安全合并，不能留下幽灵账号或让用户永久无法绑定。

## 3. 支付

### 3.1 支付方式

- 支持公众号支付、小程序支付、H5、Native、App 等能力；具体可用性取决于商户材料、AppID、域名和客户端适配。
- 支付方式开关不要用一个开关联动全部通道；每个通道独立保存和校验。

### 3.2 二维码与公众号规则

这是长期业务约束：

- 已配置公众号支付时，在微信内置浏览器直接拉起公众号支付。
- 在微信电脑浏览器、普通手机浏览器或普通电脑浏览器打开时，生成支付二维码；支付成功后页面轮询并自动跳转。
- 二维码生成失败时提供可复制的支付链接，不得只显示空白弹窗。
- 页面关闭、取消、超时要停止轮询。
- 任何修改不得随意破坏“微信内直付、微信外二维码”的规则；只有用户明确要求时才可改变。

### 3.3 商户材料

- 必填：商户号、API v3 密钥、商户私钥、微信支付公钥、回调地址、AppID、AppSecret。
- 支付回调和退款回调必须使用客户自己的公网 HTTPS 地址：`/api/pay/wx/notify`、`/api/pay/wx/refund-notify`。
- 证书和私钥保存在持久化私有目录；重建容器不能丢文件，也不进入 Git。
- 回调验签失败、金额/交易号/币种不匹配时不得改变资金状态。

## 4. 短信

- 授权中心统一保存阿里云 AccessKey、签名和模板；客户系统不应再保存公司短信密钥。
- 客户可选择授权中心短信服务，也可自行配置阿里云。
- 授权中心后台维护模板 key、模板名称、场景、阿里云模板 Code、签名、变量、计费单位和启用状态。
- 客户后台只提交模板 key、变量和业务接收人；密钥不向客户暴露。
- 发送成功/成功回执才计费；失败、拒绝和未送达必须有明确状态。
- 使用前必须准备：阿里云 AccessKey、短信签名、模板 Code、模板变量、回执签名密钥。
- 回执签名密钥用于验证阿里云状态报告；未配置时不能把未知回执计为成功。
- 客户后台「系统管理 → 短信服务」选择并保存服务提供方。选择「阿里云短信（本实例配置）」不使用授权中心套餐；选择「授权中心（统一套餐）」需要本实例接入凭据，套餐还必须在授权中心「短信服务 → 套餐管理」上架且覆盖该项目。接入、上架、启用发送和启用验证码是不同的检查，切换前先核对模板和回执，不要影响现有登录验证码。

## 5. 实名认证

- 当前支持二要素；供应商可选择阿里云、腾讯云或授权中心接入。
- 配置项包含供应商地址、AppID/Secret/Key、请求超时、启用状态、套餐和失败次数限制。
- 后台可配置同一账号/手机号/IP 的失败次数和冷却策略，防止恶意刷接口。
- 套餐支付成功后再发放额度；发送/核验失败必须返回明确原因，不记录完整证件号。
- 实名资料页面只显示脱敏信息；证件照片按权限访问，审核完成后按规则清理。
- Delta 客户后台「系统管理 → 实名服务」保留授权中心实名权益与本地启用要求。使用本实例自己的凭据接入后可查看适用套餐，不必先开启自动核验；供应商由授权中心配置。显示「未接入」时先查授权中心接入凭据及共享宿主持久配置；已接入但没有套餐时查套餐状态及适用范围，不能借用其他实例凭据。

## 6. 邮件与通知

- SMTP 设置包含主机、端口、SSL/TLS、账号、授权码、发件人；密码字段保存后不回显。
- 通知事件至少覆盖：新订单、订单状态、退款状态、投诉状态、员工审核。
- 接收角色：客户、打手、管理员、客服。
- 公众号模板使用官方字段类型（如 `thing`、`time`、`amount`），不能沿用已废弃的 `phrase` 字段。
- 短信变量和模板字段必须一一对应；模板预览、字段映射和点击链接要可配置。
- 未启用邮箱或模板不完整时，不发信时要显示具体缺失配置，不能静默丢队列。

### 6.1 公众号账号、模板与运营

- 平台运营员在授权中心「服务接入 → 微信开放平台」一次性填写第三方平台 AppID、AppSecret、消息校验 Token、EncodingAESKey。复制页面显示的授权发起域名、授权事件接收 URL 到微信开放平台，并按需要开通公众号权限、配置 API 出口白名单；未全网发布时先配置微信授权测试名单。回调公网 HTTPS 路径须能到达授权中心，反代应避免记录授权回调查询串。
- 已开通并启用公众号运营、且已接入授权中心网关的客户管理员，在「公众号运营 → 微信扫码授权」打开微信官方页面；每个公众号单独扫码确认，成功后在客户后台加入列表并同步模板。组件密钥及刷新凭据不离开授权中心；已有直连与用户登录不自动切换。客户管理页删除的是本地管理记录，不替代在微信后台取消第三方授权。
- 「服务接入 → 公众号模板」内置 19 套场景文案和数据字段建议，客户在自己的已同步模板库选择微信模板，系统按实际字段类型和标签预填，未能确认的字段由管理员选择。微信模板 ID 和正文由公众号模板库决定，不创建虚构 ID、不跨租户复制、不自动发送。
- 模板场景至少覆盖新订单、订单状态、退款/提现、投诉和员工审核；`thing` 等官方字段长度按微信当前限制截断，模板未就绪不发起微信请求。
- 公众号菜单、自动回复、渠道二维码和粉丝同步属于公众号运营数据，不是 Delta 账号、站内客服会话或业务资产；粉丝 openid 只能脱敏展示。
- 直连公众号回调地址为 `https://<客户域名>/common/wechat/callback/<公众号账号ID>`；明文模式校验 `signature`，安全模式校验 `msg_signature` 并解密 `Encrypt`，重复 `MsgId` 不重复落库。对于独立的授权中心第三方平台，两条后台复制地址分别为 `https://auth.kk520yy.com/api/wechat/open-platform/events`（授权事件）和 `https://auth.kk520yy.com/api/wechat/open-platform/messages/$APPID$`（公众号消息和事件，原样保留占位符）。后者仅验签、解密并记录已授权公众号的最近接收时间，不保存正文、不转发客服、不触发自动回复，也不切换现有业务通知发件号。
- 菜单发布、真实粉丝群发、公开图文发布属于高风险外部动作，必须二次确认并单独验收；不能与订单模板通知共用同一发送链路。

### 6.2 秒杀活动

- 入口为「营销活动 → 秒杀活动」；活动只对当前租户生效，默认停用，必须配置已上架商品、固定秒杀价、独立库存和开始/结束时间。
- 秒杀商品不支持指定打手、打手等级、优惠券或会员折扣叠加；每账号首版最多 1 单，必须登录并完成下单必填项。
- 报价、库存扣减、占位记录和订单创建在同一 MySQL 事务；库存以条件更新扣减，不依赖前端按钮或 Redis。
- 未支付订单取消后由 `flash-sale-release` 定时任务返还名额；迟到支付和对账必须另行处理，已支付售后退款不自动补库存。
- 真实秒杀下单和支付必须在 520 验收，不能把后台保存或活动上架当成已可售。

### 6.3 公众号图文与群发

- 群发任务必须经历草稿、提交审批、批准/驳回；审批人和发送人不能是同一管理员。
- 真实群发默认关闭，只有 `wechat.mass_send_enabled=true` 且任务已批准、调用方再次确认时才请求微信接口。
- 模板通知和运营群发分表、分权限、分审计；业务模板不得被用于营销群发。
- 公开图文发布、真实粉丝群发和微信草稿推送仍是高风险动作，必须在 520 使用受控测试公众号验收。

## 7. 主题与功能商城

- 主题必须在客户授权有效且后台启用后才生效；失效回退默认主题。
- 默认、暗黑、拟态三套主题都要覆盖客户 H5、打手 H5、后台 PC/H5。
- 功能商城只展示已购买且已启用的权益；未购买时显示购买入口，未启用时显示启用状态。
- 价格、上下架、维护期、授权周期和最低客户端版本变更时，未支付旧报价订单应失效；已支付未签发订单保留。
- 会员等级、优惠券、邀请奖励和实名/短信套餐都属于可配置计费对象，修改前必须检查历史订单和已领取权益。

## 8. 演示与只读

- 演示账号进入系统配置时必须是只读：隐藏保存、删除、启停和上传按钮。
- 只读不能只靠前端隐藏；演示实例的后端也要拒绝写接口。
- 520 演示站和共享组使用独立数据库、配置和镜像，不能把演示数据/密钥复制到共享组。

## 9. 配置变更验收

每次配置改动至少检查：

1. 关闭→保存→重新打开，值未被默认值覆盖。
2. 未配置时前端有明确状态，不白屏、不误报已启用。
3. 后端读取和前端展示一致。
4. 没有权限的用户看不到且调用接口会拒绝。
5. 密钥、证书、手机号、证件号不出现在日志、截图或错误消息。
