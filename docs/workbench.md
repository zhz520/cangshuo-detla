# 待办中心与消息角标

管理后台的仪表盘顶部显示待处理、紧急、未读和今日已处理。点分类查看该类任务；点「去处理」进入原有业务页面，订单、投诉、审核等条目可定位到对应记录。今日已处理显示当前角色有权查看且业务已有处理时间记录的事项。

- 顶部待办、系统通知和客服聊天分别显示各自未读。侧栏在对应菜单显示待办红点。超过 99 显示 99+。
- 移动端从客服工作台、打手中心和已登录用户的「我的」进入待办。匿名访客不请求待办接口；网页后台专属操作在移动端提示处理位置。
- 看过待办只清除自己的未读提示，不会修改原业务状态。完成、撤销或失效后自动从待办移除，状态退回或升级时重新提醒。
- 客服通知使用个人已读回执。旧版已经被标成已读的广播保持原状。
- 新订单等有业务事件的通知和聊天收到 WebSocket 提示后刷新。前台约每 20 秒合并刷新一次；后台页面停止轮询，回到页面自动恢复。

待办来源包括订单指派、投诉仲裁、接力与换人、提现及退款异常、入驻与素材审核、实名和隐私申请、超时未回复会话、正式版和维护期。用户只看到本人待支付或待确认订单；打手只看到本人邀请、指派、超时未开始的订单，以及有可提现余额时的押金补缴。审核结果沿用系统通知。实名认证待办仅在功能启用且角色有权审核时出现。

管理端权限以现有操作权限为准。待办接口不会返回联系方式、实名字段、支付配置或聊天内容。收件人与任务归属由服务端计算，不接受前端指定身份。

## 数据库与验收

后端启动执行 `db/workbench.sql`，新增两张回执表，不改动订单、提现、账户、支付、通知原表。手动升级可先执行 [迁移文件](../deploy/baota/migrations/20261106-workbench.sql)，重复运行安全。回滚时可以保留回执表。跨组件更新时先升级后端，再升级后台与 H5。更新计划中将这些组件放在同一批；GitHub 发布后由客户在后台自行安装。

后端的 `WorkbenchIntegrationTest` 默认使用 H2。也可以在隔离环境使用 MySQL 8.4：启动只监听 `127.0.0.1:17427` 的临时数据库，通过 `python deploy/qa/workbench-mysql.py` 生成空的 `workbench_qa` 表结构并导入，设置 `WORKBENCH_TEST_MYSQL=1` 再运行同一测试。脚本只读取建表语句，不导入客户数据。MySQL 验收用于覆盖新旧表不同字符排序规则、待办版本变化及幂等写入等情况。
