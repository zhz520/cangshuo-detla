# 访客影子账户与前台购买总开关

## 目标

本功能按方案 A 落地：未登录用户创建电竞业务订单时，系统自动建立一个游客影子用户，订单和支付继续使用标准 user_id，不改造订单、支付、退款、聊天和结算主流程。

第一版游客下单只在 H5 开放。小程序仍要求正式登录，因为小程序支付必须使用经过平台侧授权的有效 OpenID。

## 后台开关

订单配置中新增两个独立开关：

- order.purchase_enabled
  - 默认 true。
  - 关闭后，前台隐藏所有“立即购买”“立即点单”入口。
  - 后端 OrderService 同时拒绝创建新订单，不能通过直接调用接口绕过。
  - 已有订单仍可查看、支付、取消、退款和售后。
- order.guest_checkout_enabled
  - 默认 false。
  - 开启后，H5 未登录用户可填写手机号和 6 至 12 位查单码创建游客订单。
  - 关闭后不允许创建新游客订单，但已有游客仍可使用原凭证查单和处理存量订单。

公开站点配置返回：

- order_purchase_enabled
- order_guest_checkout_enabled

## 游客账户

游客影子用户仍写入标准 user 表，并增加：

- is_guest = 1
- openid = guest:<UUID>
- nickname = 游客<手机号后四位>
- phone = 空

手机号不写入正式用户 phone 字段，因此游客之后用同一手机号注册正式账号时不会发生手机号唯一键冲突，也不需要修改游客用户 ID。

游客凭证独立保存在 guest_checkout_profile：

- user_id
- phone_hash：手机号 HMAC-SHA256
- phone_mask：脱敏手机号
- lookup_hash：查单码 HMAC-SHA256
- privacy_version
- privacy_accepted_at

手机号和查单码明文不落库。一个手机号只能对应一个游客影子账户，同一手机号换查单码会被拒绝，避免生成多个无法管理的影子账户。

订单的 contact 默认写入本次手机号，方便客服联系。订单 user_id 仍指向游客影子用户。

## 游客流程

1. 用户在产品详情点击“立即购买”或在打手页点击“立即点单”。
2. 前台检查 order_purchase_enabled。
3. 如果已登录，走原有正式用户流程。
4. 如果未登录且 guest_checkout_enabled 开启，进入游客下单区。
5. 用户填写手机号、自定义查单码并勾选用户协议与隐私政策。
6. 后端创建或复用游客影子用户、初始化钱包、创建标准订单。
7. 返回短期 GUEST token；订单创建、支付和订单管理都使用该影子用户 ID。
8. 游客支付页不显示余额支付，只使用后台已启用的网页微信支付方式；小程序支付要求正式微信账号 OpenID，不向游客开放。
9. 游客可在首页“游客订单”入口使用手机号和查单码重新获取 GUEST token。

## 查单与绑定

公开查单接口：

- POST /guest/lookup

游客下单接口：

- POST /guest/orders

正式用户绑定接口：

- POST /guest/bind

绑定条件：

- 当前登录账号必须是正式用户，不能是游客。
- 输入的手机号必须等于正式账号已验证的手机号。
- 手机号和查单码必须匹配同一个游客影子账户。
- 游客账户不能还有待支付、已支付、履约中、退款中或争议中的订单。
- 一个游客影子账户只能绑定一个正式账号。

关联保存在 guest_user_link：

- guest_user_id
- registered_user_id
- created_at

绑定只新增关联，不修改游客 user_id、订单 user_id、支付记录或资金流水。

绑定成功后：

- 正式用户的订单列表可以包含关联游客账户的历史订单。
- 绑定用户可以查看、取消、确认、指定打手和处理售后工单。
- 原有游客订单仍保留原 user_id，审计链不断裂。

## 权限边界

GUEST token 只允许访问：

- 自己订单的详情、进度、取消、确认、换人、指定打手。
- 订单支付相关接口。
- 聊天与客服会话。
- 公共文件上传。
- 游客自己的投诉工单。

GUEST token 不能：

- 修改用户资料或访问正式钱包。
- 发起余额充值。
- 使用游客钱包余额支付，或发起小程序支付。
- 参与打赏、评价、打手入驻或其他正式会员功能。
- 管理其他游客或正式用户的数据。

ProjectMaintenanceFilter 仍对 GUEST 业务接口执行域名和维护期校验。

## 隐私和统计

- 游客影子用户默认从管理员用户列表、新用户统计、用户数和消费榜中排除。
- 游客订单仍计入订单量和成交金额，避免经营数据失真。
- 公告群发只发送给正式用户和打手。
- 游客手机号和查单码只保存 HMAC 摘要；日志不得输出明文凭证。
- identity.hash-pepper 必须长期稳定。更换后已有游客凭证将无法查询。

## 数据迁移

启动兼容：

- DatabaseCompatibility 自动增加 user.is_guest。
- 自动创建 guest_checkout_profile 和 guest_user_link。
- 自动补齐两个订单配置开关。

独立迁移文件：

- deploy/baota/migrations/20261106-guest-checkout.sql

迁移文件会先检查列是否存在，可重复执行；两张游客表和两个配置项同样按幂等方式创建。

## 验证

已覆盖：

- 游客影子用户创建。
- 普通用户手机号查询不返游客。
- 游客凭证不能签发 USER token。
- 手机号和查单码以摘要保存。
- 游客重复查单。
- 未完成游客订单禁止绑定正式账号。
- 完成订单后建立关联且不修改游客 user_id。
- order.purchase_enabled 关闭时在用户校验前拒绝新订单。
- 游客不能调用余额支付或小程序支付接口。
- 待确认、履约中、退款中和争议中订单均禁止绑定正式账号。
- 全局购买入口结构检查。
- H5 构建通过。
