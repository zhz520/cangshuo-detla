# 阿里云短信模板申请与配置说明

适用平台 JAX　更新日期 2026年10月25日

平台使用1个验证码模板和4个通知模板。先在阿里云申请并审核通过，再把每个模板的 Code 填入平台后台对应位置。以下内容按当前项目发送逻辑编写，模板名称中的“JAX平台”可按实际网站名称调整，场景说明应与真实业务一致。

## 1 五个模板分别做什么

| 模板 | 接收对象 | 触发方式 |
| --- | --- | --- |
| 登录验证码 | 主动申请验证码的用户 | 手机号登录或手机号绑定验证 |
| 消息提醒 | 用户或打手 | 聊天页手动发送提醒；客服也可提醒用户或打手 |
| 通知老板结单 | 下单用户 | 打手在聊天页手动发送结单提醒 |
| 打手被指派 | 被指派的打手 | 订单指派后由后台自动通知 |
| 打手被邀请 | 被邀请的打手 | 收到订单组队邀请后自动通知 |

消息提醒不是每收到一条聊天消息就自动发短信。“打手被邀请”是订单组队邀请，不是邀请新用户注册。

截图中的 YOUR_SMS_TEMPLATE_… 是占位内容，不能用于发送短信；需要替换为自己阿里云账号中审核通过的模板 Code。

## 2 在阿里云申请模板

1. 登录阿里云短信服务控制台，先准备已审核通过的短信签名。
2. 进入“国内消息 → 模板管理 → 添加模板”，按实际控制台菜单操作。
3. 登录验证码选择“验证码”类型；其余4个选择“通知短信”类型。
4. 选择关联签名，填写模板名称、模板内容和场景说明。可参考下一节逐项填写。
5. 提交审核。需要补充资料时，如实提供平台登录页、相关功能页面和可访问的网站地址。
6. 审核通过后复制模板 Code，再填写平台后台。不能把模板名称、短信正文或签名名称当成 Code。

短信签名和模板都需要通过审核。签名单独配置，短信正文无需再手动添加签名括号。模板申请及类型选择可参照[阿里云官方申请说明](https://help.aliyun.com/zh/sms/user-guide/create-message-templates-1)。

## 3 可直接参考的填写内容

### 登录验证码模板

**模板类型：** 验证码

**模板名称：** JAX平台登录验证码

**模板内容：**

您的验证码为${code}，5分钟内有效，请勿泄露给他人。

**场景说明：**

用于JAX平台用户手机号登录及手机号绑定验证。仅在用户主动申请时发送，验证码为6位数字，5分钟内有效。短信示例：您的验证码为123456，5分钟内有效，请勿泄露给他人。平台地址：https://jax738.idcgov.cn。

变量名必须为 code，模板中保留完整的 ${code}，不要填成固定的123456。123456只用于场景说明中的短信示例。若控制台需要选择变量属性，选择数字并按6位验证码设置。

审核通过后的 Code 填入平台后台“短信验证码模板 Code”。截图上方如提示未开启验证码防盗刷监控，可按阿里云页面指引配置；平台已有图形验证码和发送频控，仍需保留。

### 消息提醒模板

**模板类型：** 通知短信

**模板名称：** JAX平台消息提醒

**模板内容：**

您有新的服务消息，请登录JAX平台查看。

**场景说明：**

用于JAX平台已绑定手机号的用户或服务人员接收服务沟通提醒。在现有服务会话中，由用户、服务人员或客服手动触发，提醒聊天对方登录平台查看消息，不用于营销推广。短信示例：您有新的服务消息，请登录JAX平台查看。平台地址：https://jax738.idcgov.cn。

审核通过后的 Code 填入“消息提醒模板 Code”。

### 通知老板结单模板

**模板类型：** 通知短信

**模板名称：** JAX平台订单完成提醒

**模板内容：**

您的订单服务已完成，请登录JAX平台查看并确认。

**场景说明：**

用于JAX平台服务人员完成订单服务后，向下单用户发送订单完成提醒。由服务人员在聊天页主动触发，提醒用户登录平台核实服务情况并确认订单，不用于营销推广。短信示例：您的订单服务已完成，请登录JAX平台查看并确认。平台地址：https://jax738.idcgov.cn。

审核通过后的 Code 填入“通知老板结单模板 Code”。发送提醒本身不会替用户确认完成订单。

### 打手被指派模板

**模板类型：** 通知短信

**模板名称：** JAX平台订单指派通知

**模板内容：**

您有新的服务订单，请登录JAX平台查看并处理。

**场景说明：**

用于JAX平台向已入驻且绑定手机号的服务人员发送订单指派通知。订单被指派后，系统自动发送，提醒被指派人员查看并处理订单，不用于营销推广。短信示例：您有新的服务订单，请登录JAX平台查看并处理。平台地址：https://jax738.idcgov.cn。

审核通过后的 Code 填入“打手被指派模板 Code”。

### 打手被邀请模板

**模板类型：** 通知短信

**模板名称：** JAX平台订单组队邀请

**模板内容：**

您收到订单组队邀请，请登录JAX平台查看并处理。

**场景说明：**

用于JAX平台订单服务人员邀请其他已入驻人员共同处理订单时，通知被邀请人员。系统在组队邀请产生后自动发送，不涉及邀请注册、用户拉新或营销推广。短信示例：您收到订单组队邀请，请登录JAX平台查看并处理。平台地址：https://jax738.idcgov.cn。

审核通过后的 Code 填入“打手被邀请模板 Code”。

**4个通知模板均使用固定文字，不添加 ${name}、${orderNo} 等变量。当前程序发送这4类短信时不传变量，自行添加变量会与程序不匹配。** 通知内容应反映真实服务场景，审核要求以阿里云[通知短信模板规范](https://help.aliyun.com/zh/sms/user-guide/notification-template-specifications)为准。

## 4 平台后台怎么填写

进入平台管理员后台“系统管理 → 系统配置 → 短信配置”，先填写账号、签名和模板，再保存配置。

| 后台字段 | 填写内容 |
| --- | --- |
| 阿里云 AccessKey ID | 具备所需短信发送权限的 RAM 用户 AccessKey ID |
| 阿里云 AccessKey Secret | 对应的 AccessKey Secret，仅填在后台密钥位置 |
| 阿里云短信 Endpoint | dysmsapi.aliyuncs.com |
| 阿里云短信签名 | 自己已审核通过的签名名称，保持完全一致 |
| 短信验证码模板 Code | 登录验证码模板审核通过后的 Code |
| 消息提醒模板 Code | 消息提醒模板审核通过后的 Code |
| 通知老板结单模板 Code | 订单完成提醒模板审核通过后的 Code |
| 打手被指派模板 Code | 订单指派通知模板审核通过后的 Code |
| 打手被邀请模板 Code | 订单组队邀请模板审核通过后的 Code |

Code 通常以 SMS_ 开头，以阿里云实际生成的值为准。不要保留 YOUR_ 开头的占位内容，也不要直接使用其他账号的示例编号。AccessKey Secret 不要放进短信正文、场景说明或截图资料。

后台有两个相关开关：“启用阿里云短信提醒”是短信总开关，聊天提醒和后台业务通知都会受它控制；“启用短信验证码登录”控制验证码功能，验证码发送需要两个开关同时开启。总开关开启前，应核对通知模板，避免只准备验证码却触发尚未配置好的业务通知。

## 5 配置完成后的检查

1. 确认签名和需要使用的模板均已审核通过，阿里云短信账户具备发送条件。
2. 核对5个 Code 与后台字段一一对应，保存后重新打开页面检查。
3. 准备自己的测试手机号，按需要开启短信总开关；测试验证码时另行开启验证码开关。
4. 验证码检查能否收到6位数字，以及手机号登录流程是否正常。
5. 通过测试会话检查消息提醒和结单提醒；通过测试订单检查指派通知和组队邀请。指派及邀请会影响订单，仅在测试订单上操作。
6. 发送失败时结合平台提示及阿里云发送记录排查，先解决原因，不连续重复点击。

实际发送短信会产生阿里云短信费用。后台“打手短信提醒扣费金额”是平台对打手设置的扣费规则，与阿里云实际短信单价不是同一项。

普通打手抢单使用的是图形验证码，与这里的短信验证码模板无关，不需要为抢单另申请短信模板。

## 6 常见问题

| 问题 | 检查位置 |
| --- | --- |
| 提示模板不存在或无权限 | 是否使用自己账号下已通过审核的 Code，AccessKey 是否有对应权限 |
| 提示变量不匹配 | 验证码是否使用 ${code}，4个通知模板是否误加变量 |
| 提示短信提醒未开启 | 是否已保存短信总开关 |
| 提示短信登录暂未开放 | 总开关与验证码开关是否同时开启 |
| 无法给对方发送提醒 | 对方是否绑定手机号，当前会话是否支持该提醒 |
| 提示发送过于频繁 | 等待冷却时间，不连续发送 |
| 申请模板审核未通过 | 查看阿里云具体原因，如实补充签名、业务场景和网站证明材料 |

模板示例用于填写参考，不保证审核通过。若平台名称、业务页面或模板内容需要调整，应按真实场景提交；模板变更后以阿里云实际审核结果及生成的 Code 为准。
