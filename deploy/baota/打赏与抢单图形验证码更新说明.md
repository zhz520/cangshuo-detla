# 打赏与抢单图形验证码更新

## 后台入口

- **系统管理 → 打赏与抢单设置**：打赏开关、金额范围、有效天数、每日次数、服务费，以及图形验证码有效期、错误次数和刷新间隔。
- **打手等级分类 → 编辑 → 抢单验证**：按等级设置是否需要验证码。
- **打手管理 → 编辑 → 抢单验证**：跟随等级、必须图形验证、免验证。
- **打手管理 → 详情 → 抢单验证记录**：刷新、失败和通过次数，以及最近十笔接单。计数保留至最近活动后的三十天。
- **打赏记录**：按客户 ID、打手 ID、订单号、日期和状态查询；详情包含双方余额快照和冲正信息。
- **系统管理 → 操作日志**：查询规则变更前后值、等级与个人例外变更及冲正原因、操作管理员 ID。

## 客户与打手操作

客户打开自己已完成、待确认或已评价的订单，点击“打赏打手”，选择金额并使用余额支付。余额不足可前往现有充值页面，充值后返回原订单继续操作。订单最多打赏一次，不能给自己或其他客户的订单打赏。

打手公开主页只为符合条件的已登录客户显示打赏入口，选择历史完成订单后进入订单详情打赏。打赏关闭、订单已打赏或超出有效期时，不显示新的打赏入口。

打手收入总览显示其中的打赏收入，收入明细区分打赏到账和冲正扣款，并保留来源订单。订单佣金、订单金额和分成比例保持原有规则。

需要验证的打手在接单大厅或订单详情点击接单，输入图形验证码后确认。验证码绑定当前打手、订单和设备，只能使用一次。验证失败或订单已被抢走后，需要重新获取验证码；刷新仍受后台间隔限制。免验证打手仍受账号状态、审核状态、订单归属和并发接单上限约束。

## 默认值

| 设置 | 默认值 |
| --- | --- |
| 打赏开关 | 关闭 |
| 金额范围 | 1～200 元 |
| 完成后有效期 | 30 天 |
| 每客户每日次数 | 10 次 |
| 每打手每日接收次数 | 5 次 |
| 同客户对同打手每日次数 | 5 次 |
| 平台服务费 | 0% |
| 图形验证码有效期 | 120 秒 |
| 单个验证码最多错误次数 | 5 次 |
| 刷新间隔 | 10 秒 |
| 等级抢单验证 | 开启，可逐个等级调整 |
| 打手个人例外 | 跟随等级 |

规则保存后对新请求生效。已经支付的打赏按当时的金额和服务费快照处理；已经发出的验证码沿用生成时的有效期与错误次数。

## 异常打赏冲正

管理员在“打赏记录”点击“冲正”，填写原因后执行。打手可用余额充足时，一次性扣回打手实收并向客户退还原打赏金额，原服务费同时撤销。双方各新增一条流水，原打赏记录保留。

打手可用余额不足时，记录“待追回”和需追回的实收金额。此时双方余额保持不变，客户退款尚未完成。余额充足后，管理员点击“重试冲正”。系统不会扣成负数，也不会重复退款。

## 宝塔更新顺序

1. 在宝塔数据库中备份当前数据库，并保留当前后端包、管理端和 H5 文件。
2. 在现有数据库执行 `migrations/20261024-reward-grab.sql`。脚本可以重复执行，已有规则和记录不会被覆盖。不要重新导入完整 `delta_game.sql`。
3. 更新后端包、管理端和 H5，使用同一发布包中的三个构建产物，然后重启后端。
4. 进入“打赏与抢单设置”，打赏开关先保持关闭；核对各等级的抢单验证设置和个人例外。
5. 在隔离测试环境完成真实 Redis 验证及 MySQL 并发测试后，用测试订单验证两个入口，再按运营安排开启打赏。
6. 数据库升级为新增表和字段。回退应用时恢复旧后端和前端构建，保留新增表、资金记录和流水，不删除升级数据。

本轮功能只使用余额和图形验证码，没有增加短信验证或新的微信支付方式。

## 验证范围

自动化测试覆盖打赏事务、幂等、并发次数限制、余额不足、冲正与待追回、越权访问、金额限制、开关和期限、抢单唯一性、免验证及个人覆盖、接单上限和接单前敏感字段隐藏。

H5 和管理端需要同时完成构建和浏览器交互检查。真实 Redis 的验证码过期、一次消费、刷新限流和跨账号、跨订单、跨设备限制，以及 MySQL 生产隔离级别下的并发验证，须在隔离环境完成，不能用内存数据库测试结果替代。
