# 宝塔可视化部署

适用于已安装宝塔和 Docker 的 Linux x86_64 服务器。三个业务镜像的真实标签均为 `tagname`，只发布了 amd64 镜像；这不是需要替换成 latest 的占位符。

本说明配套 ZIP 是首次安装包，不能覆盖已有生产数据库。它根据当前仓库配置补齐编排和管理员初始化，尚未在你的服务器实测；远程业务镜像也未与源码逐文件比对。

## 1. 上传解压

1. 宝塔左侧“文件”，进入 `/www`。
2. 上传 `delta-baota.zip`，解压到 `/www`。
3. 检查最终路径：`/www/delta/docker-compose.yml`、`/www/delta/.env`、`/www/delta/nginx.conf`、`/www/delta/initdb/01-schema.sql`、`/www/delta/initdb/02-admin.sql`。
4. 如解压产生多余一层目录，用文件管理器将 `delta` 文件夹移动到 `/www/delta`。
5. `.env` 是隐藏文件，必要时开启显示隐藏文件。包内密钥已随机生成，初次测试不必手动填入。

数据库会单独创建普通用户 delta_game。数据库密码不是宝塔面板已有数据库的 root 密码。MySQL、Redis 不映射到公网，也不需要另装宝塔 MySQL、Redis、Java、Node。

## 2. 创建编排

1. 宝塔“Docker” → 顶部“容器编排” → “创建编排/添加编排”。
2. 名称填 `delta`。
3. 如果支持从文件创建，选择 `/www/delta/docker-compose.yml`；如果只有编辑框，在“文件”中打开该文件，复制完整内容到编排编辑框。
4. 点击确认/创建，等待五个镜像拉取与容器启动。

所有挂载与 env_file 都使用 `/www/delta` 的绝对路径；宝塔复制编排文件到内部目录时，仍可找到配置和初始化脚本。

如果面板创建失败且原因是 Compose 命令兼容问题，在宝塔左侧“终端”只执行一行：

```bash
/usr/bin/docker-compose -p delta -f /www/delta/docker-compose.yml up -d
```

此处沿用你截图中配置的 `/usr/bin/docker-compose`。如果服务器实际使用 Compose 插件，将开头替换成 `docker compose`。

## 3. 等待初始化完成

到“Docker” → “容器”查看：

- `delta-mysql`：运行，健康检查通过。
- `delta-redis`：运行，健康检查通过。
- `delta-backend`：运行；查看日志出现 Spring Boot 的 Started 信息。
- `delta-admin-ui`：运行。
- `delta-h5`：运行。

MySQL 首次自动创建数据库、导入表结构并创建管理员。后端等 MySQL 与 Redis 健康后启动；网页容器运行不代表后端已经就绪。

`initdb` 脚本只在空数据目录首次启动时执行。已有数据时，修改脚本或重启都不会重新导入。不要反复手动导入 `01-schema.sql`，其中含 DROP TABLE。当前初始化 SQL 已含 recharge_bonus 列，无需重复执行根目录的充值迁移脚本。

## 4. 绑定域名并访问

1. 将管理后台域名和 H5 域名的 DNS A 记录解析到服务器公网 IP。
2. 宝塔“网站” → “反向代理”（不同版本入口可能不同），分别创建两项：管理后台代理目标 `http://127.0.0.1:8081`，H5 代理目标 `http://127.0.0.1:8082`。
3. 代理整个 `/` 路径；若有 WebSocket 支持开关则开启。
4. 各站点申请 SSL 证书并开启 HTTPS；安全组只放行必要的 80、443。
5. 管理后台和 H5 容器端口只绑定 `127.0.0.1`，禁止在安全组或防火墙直接公开 8081/8082。管理员账号和随机初始密码见本机部署包旁的“登录信息.txt”。README 的演示密码不适用。

支付和微信小程序默认关闭。H5 手机号登录必须配置并验收阿里云短信 OTP 后才能启用，系统不再提供共享固定验证码。

启动前必须把 `.env` 中的 `ALLOWED_ORIGINS` 替换为管理端和 H5 的实际 HTTPS Origin（逗号分隔、不带路径）。生产启动会校验 JWT、数据库、Redis 和来源配置，继续保留占位值会主动拒绝启动。

该包补了容器 Nginx 的 `/ws/` 代理。源码 H5 的 `VITE_WS_BASE_URL` 在构建时写入，目前源码生产配置为 `wss://your-domain.example/ws/chat`。作者发布镜像里的实际构建值尚未核实；如果 H5 聊天请求错误域名，需要用自己的 H5 域名修改 delta-mp/.env.production 后重新构建 H5 镜像，仅修改容器 .env 无效。管理端源码则按当前访问地址建立 WebSocket。

## 拉取镜像失败时

查看“Docker” → “容器编排”中的执行日志。连接超时说明尚未下载成功，不是程序启动错误。

- 有已确认可用的镜像加速服务时，在 Docker 设置中填写它。
- 或从原部署文档获取 `delta-game-images.tar`，通过“Docker” → “本地镜像”中的导入功能导入（若你的版本提供该入口），再创建编排。
- 没有导入入口时，上传 TAR 到 `/www/delta`，终端执行 `docker load -i /www/delta/delta-game-images.tar`，再通过面板创建编排。
- 离线包的下载可用性与内容未核实；导入后先确认存在所需的五种镜像和相同标签。

不要依据设置页的提示就反复重启整个 Docker 服务，避免影响其他项目。

## 数据与常见故障

- MySQL 数据：`/www/delta/data/mysql`；Redis：`/www/delta/data/redis`；上传文件：`/www/delta/data/upload`。
- 删除、重建容器不会自动删除这些目录。不要删除 data 目录来解决启动错误。
- `.env` 初始化数据库后再改 MYSQL_PASSWORD，不会自动更改 MySQL 现有账户密码，需要同步在数据库中改密码。
- 8081/8082 端口冲突：修改编排中的 `127.0.0.1:8081:80` / `127.0.0.1:8082:80` 左侧数字后更新编排，并同步修改宝塔反代目标；不要公开这两个端口。
- 网页能打开但登录 502：查看 delta-backend 日志，再确认 MySQL、Redis 健康状态。
- `exec format error`：核对服务器是否为 ARM，当前三个业务镜像只发布 amd64。
- `not a directory`：检查绝对路径是否正确，尤其 nginx.conf 必须是文件。

包内含数据库密码、密钥和管理员初始化信息，应保存在受控位置。无需将这些内容发送到聊天或提交到 Git。
